## 3. Inputs and worked example

### Exact scores and total order

Preserve the frozen notation literally in the internal contract:

```text
rank_key(doc) = (-score_f64_bits_order, document_id_utf8_bytes)
```

Here `score_f64_bits_order` means a **numeric-monotone** representation of a
finite f64 score, not raw IEEE bits sorted as unsigned integers. Canonicalize a
computed zero score to positive zero before ranking/serialization. One proposed
implementation maps finite bits `b` to `!b` when the sign bit is set, otherwise
`b ^ (1_u64 << 63)`; compare mapped keys descending, then exact canonical UTF-8
document-ID bytes ascending. Do not literally negate an unsigned key. Reject
duplicate canonical IDs at snapshot construction and preserve their bytes
without locale collation or query-time Unicode normalization.

For dimension $D$, provided f32 query $q$ and record vector $v$, promote **each
operand to f64 before multiplication**. Initialize positive-zero accumulators and
visit dimensions $j=0,\ldots,D-1$ in order:

$$s=\sum_j \operatorname{f64}(q_j)\operatorname{f64}(v_j),\qquad
a=\sum_j \operatorname{f64}(q_j)^2,\qquad
b=\sum_j \operatorname{f64}(v_j)^2.$$

Dot score is $s$. Cosine score is $s/(\sqrt a\,\sqrt b)$, with each square root
computed separately, then multiplied, then one division. Freeze that operation
order, round-to-nearest implementation/toolchain and no-FMA/no-reassociation
policy. `(q[j]*v[j]) as f64` is different: it rounds the product in f32 first.
Do not pre-normalize vectors in place or replace the denominator with
$\sqrt{ab}$. Check every query/eligible vector component and final result for
finiteness. This is exact represented arithmetic under the declared execution
contract, not exact real-number cosine on every machine.

Proposed zero policy: dot mode accepts a zero query/vector and produces zero
ties; cosine mode rejects a zero query before scanning, and rejects the complete
query on the first authorized zero-norm record in canonical ID order. Return no
partial ranking. Unauthorized zero/nonfinite/wrong-dimension payloads are not
inspected by the scorer. Store-wide integrity verification is a separate
prerequisite and may refuse a corrupt snapshot before any query begins.

### Inherited six-record example

Use 384-dimensional f32 vectors with unlisted coordinates zero, query $e_0$ and
IDs `doc-0000` through `doc-0005`. All vectors are provided synthetic basis
vectors, not embeddings. Text for index $i$ is ASCII `document ` followed by
unpadded decimal $i$, without LF. Manifest binds exact text/vector bytes and the
fixed synthetic-fixture provenance. Authorize only indices 1, 2, 3 and 4.

| Index | Vector | Authorized | Dot / cosine score |
| --- | --- | --- | --- |
| 0 | $e_0$ | no | not computed |
| 1 | $e_0$ | yes | 1 / 1 |
| 2 | $e_1$ | yes | 0 / 0 |
| 3 | $-e_0$ | yes | -1 / -1 |
| 4 | $e_0$ | yes | 1 / 1 |
| 5 | $e_0$ | no | not computed |

For $k=3$, both modes return IDs `[doc-0001,doc-0004,doc-0002]` with score bits
`[0x3ff0000000000000,0x3ff0000000000000,0x0000000000000000]`.
The score tie is settled by the bytes of 1 before 4, not insertion order.
Requesting five returns those three plus `doc-0003`, score bits
`0xbff0000000000000`; exactly four records are eligible. A raw unsigned-bit
descending sort would incorrectly put the negative score first.

Remove authorization for record 1 in a **new authorization epoch**, leaving the
store unchanged: the three returned IDs become `[doc-0004,doc-0002,doc-0003]`.
Changing its text to `changed document 1` instead requires a new content hash and
snapshot; unchanged vector/permission keeps its rank but changes cited bytes and
provenance. Neither mutation edits an immutable old snapshot in place.

A metric-distinction fixture uses three provided vectors with first coordinates
`a=[2,0]`, `b=[1,1]`, `c=[0,1]` and query `[1,1]`, all remaining coordinates
zero. Dot scores are `[2,2,1]`, so IDs a,b,c rank in that order; cosine ranks b
first, then a,c tied at the represented evaluation of $1/\sqrt2$. This explains
why vector magnitude affects dot but not ideal cosine. Derive exact f64 output
bits from the declared ordered primitive in future Rust; do not copy a rounded
decimal into a golden. The mathematical expressions are the independent oracle;
bit parity is asserted between adapters using the same canonical computation.

### Complete prompt admission, with literal token accounting

Use a separate **test-only zero-merge byte-tokenizer** fixture from the existing
tokenizer construction, not a model acquisition. Assemble whole evidence units
in rank order. Each unit is the exact ASCII string
`[doc-0001]\ndocument 1\n` with the matching ID/text substituted; it is 22 bytes
for these one-digit records. The literal prefix is `Q:x\n` (4 bytes), suffix
`A:` (2 bytes). The full ID→content/vector/provenance hash mapping stays in the
returned citation manifest; the prompt visibly carries the corresponding ID.
These terse wrappers are arithmetic-test data, not the final trust-label prose.

Tokenize the **complete assembled bytes once** with `encode_document` in this
fixture, including its BOS/EOS: two units make 50 content bytes and 52 tokens;
with output reserve 8 and admitted context 60, total is exactly 60. Three units
make 74 prompt tokens and total 82, so include only the first two. Retrieved IDs
remain `[doc-0001,doc-0004,doc-0002]`; included IDs are `[doc-0001,doc-0004]`.
At context 59, two no longer fit and one unit yields 30 prompt tokens plus 8.
No half record, dangling citation, split UTF-8 sequence or silently shortened
output allowance is emitted.

For a real accepted tokenizer/template, do not add separately tokenized lengths:
BPE merges can cross boundaries. Rebuild and tokenize each complete prefix of
whole evidence units, including all system/user wrappers, separators, special
tokens and output reserve. Choose the largest rank-prefix whose exact total
fits the Chapter 73 admitted policy; test every bounded candidate rather than
assume token counts are monotonic under arbitrary merges. Bound assembly bytes
before tokenization. If even zero units plus the base prompt/reserve cannot fit,
return `ContextBudgetExceeded`; do not truncate the user's prompt implicitly.
Production BOS/EOS/template behavior must follow the accepted tokenizer contract,
not the pedagogical `encode_document` choice above.

Use structured wrapper fields/escaping so document text is represented as an
untrusted evidence value and cannot forge another trusted metadata field. This
preserves representation boundaries; it does **not** prove a model will ignore
malicious instructions in that value. Recheck the authorization epoch under a
read lease immediately before releasing any context/citation bytes. A changed
epoch aborts the whole prepared result; a retry is a new bounded query, not a
patch to an old result. Final service exposure must retain this lease or perform
the same checked handoff atomically.

## 5. Test and failure matrix

Exact basis scores/bits, canonical bytes, IDs, counts, provenance and state
transitions use equality. General same-oracle adapter/restart scores also use
exact bits. Independent cosine mathematics may be displayed symbolically with
rounded explanatory decimals, but an approximate comparison cannot settle ties
or replace the frozen rank. Pin the f64/sqrt execution environment before golden
generation; cross-platform changes require declared compatibility evidence.

| `ten_inherited_score_fixtures` | Two metrics × five basis queries; six-record ranks exactly as §3. Dot/cosine agreement here proves this basis fixture, not general metric equivalence. |
| `promotion_precedes_product` | Use f32 values `1+2^-23` for both operands: f64 product retains the `2^-46` term that f32 multiplication discards. Also use ordered `[1,2^54,-2^54]` products: increasing left-to-right f64 reduction gives 0, while `1+(2^54-2^54)` gives 1. No FMA or reassociation/parallel reduction substitution. |

## 6. Teaching and surface commitments

Opening problem: model parameters do not identify which local record an answer
used, and selecting the closest vector can expose a record the requester may
not read. Explain the need for permitted, traceable input before introducing
similarity or top-k. The opening asks no learner questions. Do not describe
retrieval as installing knowledge or proving an answer correct.

Use the progression **problem → solution → history → visualization and optional
practice**. In the solution, first explain the six-record authorization/result
table and its tie, then connect its loop to general dot/cosine and total-order
notation. Follow the selected records through exact content hashes, complete
prompt tokenization, budgeted inclusion and citation manifest. Explain why the
authorization check occurs twice: filtering prevents denied records affecting
selection; final epoch validation prevents a once-valid result escaping after
revocation. History supplies the bounded RAG/pgvector contrast only after this
mechanism is understood; it neither switches the architecture nor adds a store.

Define D as vector coordinates, N as stored records, k as requested maximum
results, eligible count as records permitted by the frozen host policy, score
as a dimensionless metric result, epoch as policy-version identity and context
budget in **tokens**. Distinguish token IDs from text bytes; snapshot identity
from document ID; content hash from vector hash; retrieved records from included
evidence units; citation membership from entailment. Explain promotion and
ordered reduction as the reproducibility contract, not a claim that f64 makes
real-number arithmetic exact. All learner-facing formulas use the math pipeline.

Required optional practice, after the explained examples:

- Reproduce the four eligible six-record ranks for k=5. Checked answer is IDs
  1,4,2,3 with scores1,1,0,-1; only four may be returned.
- Inspect dot versus cosine on the a,b,c fixture. Explain b's first cosine rank
  through direction rather than document truth; dot's a/b tie uses ID bytes.
- Reproduce the 52+8 token admission at context60 and explain why retrieved doc2
  cannot be cited after whole-unit truncation. At59 the included prefix is doc1.
- Trace revocation between rank and exposure. The old result is refused and
  a fresh epoch/query yields4,2,3; no previously ranked payload is leaked.
- Diagnose zero norm, wrong dimension and changed content hash separately.
  Checked answers identify cosine undefinedness, shape mismatch and provenance
  mismatch, with no partial context in each failing case.
- Inspect the scripted false answer with a valid citation ID. Membership passes
  while entailment remains unproved; the pipeline must not label it factual.

None is a prediction exercise; every required outcome is already explained and
optional practice may be skipped without losing the lesson's causal chain.
Future Rust excerpts must show the taught checks/loops, not merely call their
proposed high-level API. The historical Rust contrast can disable retrieval in
the same prompt assembler and compare visible provenance; it is not a simulation
of the paper's trained neural retriever.

Freeze surface requirements from these commitments before formal review. A score
column names its metric, finite representation and ordering; an authorization
status says host policy rather than a document's claim about itself. A rank or
citation caption names snapshot/eligibility scope and what the IDs identify.
Token-budget captions state that wrappers, controls and output reserve count.
Each independently exposed error names the failed condition without disclosing
denied record details. Metadata/SEO/catalog and cheat-sheet entries must retain
the local provided-vector scope and not promise trustworthy answers. Navigation
