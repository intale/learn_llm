The problem: verified text is not yet training input A matching checksum tells us which text we have, not whether every record should enter a training corpus. A record may be malformed, too large for the processing budget, or contain a literal marker that our chosen policy excludes. Some records need review rather than an automatic yes or no. Deleting every excluded record without keeping its reason loses useful evidence. Reporting only the final retained count also hides which records each rule actually examined. If an early rule stops a record, later rules cannot truthfully report that the record passed or failed them. The solution here is an ordered filter with three dispositions: Retained: a candidate for the next data-processing stage, not a guarantee of quality, privacy or permission. Rejected: excluded by an automatic rule. Manual review: withheld from downstream training input. This example has no approval override. The first rule in the configured order that rejects a record or holds it for manual review supplies that record’s first terminal decision. Evaluation stops there; later rules are not evaluated for that record. If a record survives every rule, it is retained with no first terminal rule. The report preserves each record’s disposition, the rules actually evaluated, any first terminal rule and the record’s reference to its raw source. It does not copy excluded text into public findings.
Eight records, with explicit boundaries Everything in the worked example is course-authored synthetic data. It is not a filtering result for TinyStories. The two source names fixture-train and fixture-validation preserve their raw-source provenance; they do not create the final training, validation or test split. The selected framing policy, end-of-input-delimited-v2, recognizes the ASCII marker <|endoftext|> only when it occupies an entire physical line. A marker line may end with LF, CRLF or end of input. Its bytes are a delimiter, not payload text. The same marker inside an ordinary text line is not a delimiter. End of input also closes a remaining nonempty payload, even without a final newline. End of input immediately after a separator creates no extra record. Consecutive separators create an empty payload that the filter can reject. A failed read is an error, not an end-of-input boundary. These rules are selected explicitly; the reader does not guess another format after a failure. For this fixture, append b"<|endoftext|>\n" after every record below, in table order within each source. Every separator therefore contributes 14 bytes. In Rust literals, \n denotes one LF byte and \xff one byte that is invalid as standalone UTF-8. The solution: stop once, count at every reached rule The fixture deliberately uses small thresholds so each failure is visible: Reject a raw payload above 64 bytes before decoding it. Reject invalid UTF-8. Normalize the decoded text and reject fewer than 4 normalized UTF-8 bytes. Reject fewer than 1 ASCII letter. Reject the literal demo-key=CANARY, matched without ASCII case distinctions. Hold the literal contact=, matched case-sensitively. Hold text below the configured ASCII-letter share. Normalization replaces CRLF pairs with LF, then trims only space, tab, CR and LF at the two edges. It preserves case, internal spaces and other Unicode characters. Length after normalization is measured in UTF-8 bytes, not characters or tokens. For the last rule, count Unicode scalar values other than the six ASCII whitespace characters: space, tab, LF, vertical tab, form feed and CR. The numerator counts ASCII letters among those values. Compare a configured fraction using checked integer cross-products, rather than rounding a floating-point ratio. A zero denominator is unavailable and sends a reached record to review; it is not an observed share of zero. The fixture’s threshold is 0/1, so its last survivor passes this rule. These thresholds are not the full-corpus policy. The planned corpus policy uses a 65{,}536-byte raw limit, at least 16 normalized bytes, at least 8 ASCII letters and an ASCII-letter share of at least 1/2, with its own selected marker lists. For example, the fixture’s short secret record would reach a different first terminal rule under a stricter length threshold. None of the fixture’s rates are measurements of a real corpus. For a named rule k, report its terminal fraction using the population that actually reached it: r_k=\frac{n_{\mathrm{disposition},k}}{n_{\mathrm{seen},k}}

When n_{\mathrm{seen},k}=0, the report stores unavailable, not zero. Four records reach the secret-marker rule, and it rejects two. Its terminal fraction is 2/4=1/2. Dividing by the original eight records gives 2/8=1/4, a different quantity: that rule’s terminal decisions as a fraction of all input records. Do not label the second quantity as the reached-population rate. The reached populations are 8,7,6,5,4,2,1, leaving one retained record. The final dispositions must conserve the input count: 8=1_{\mathrm{retained}}+6_{\mathrm{rejected}}+1_{\mathrm{manual\ review}} A binary exclusion summary gives 7 ineligible records, but those are 6 rejections plus 1 pending review. Calling all seven “rejected” discards the distinction needed to explain their outcomes.
Rust owns the framing and decisions The framer accepts an ordinary Read source. The output interface separates retained rows from body-free exclusion findings, without requiring a directory, filename, HTTP source or storage backend. Supporting libraries provide JSON encoding and SHA-256; the course code owns boundaries, rule order, terminal decisions and accounting. A bounded buffer retains only payloads within the selected size limit. An oversized record is drained to its boundary and counted without retaining its whole body. Read-buffer boundaries do not split records or invalidate a Unicode character: UTF-8 decoding happens on the complete bounded payload. Read the selected raw source completely and check its byte count and digest after framing. rust/crates/llm-from-scratch/src/data/stream.rs#source-bound-framing pub fn scan_source<R: Read, F>( reader: R, source: &SourceBinding, policy: &FramingPolicy, mut visit: F, ) -> Result<ScanSummary, DataError> where F: FnMut(Frame) -> Result<(), DataError>, { policy.validate()?; let limit = source.bytes().checked_add(1).ok_or(DataError::Overflow)?; let mut reader = reader.take(limit); let mut buffer = [0_u8; STREAM_BUFFER_BYTES]; let mut hasher = Sha256::new(); let mut observed = 0_u64; let mut framer = Framer::new(policy)?; loop { let length = reader.read(&mut buffer)?; if length == 0 { break; } observed = observed .checked_add(length as u64) .ok_or(DataError::Overflow)?; if observed > source.bytes() { return Err(DataError::SourceMismatch); } hasher.update(&buffer[..length]); for &byte in &buffer[..length] { framer.feed(byte, &mut visit)?; } } framer.finish(&mut visit)?; if observed != source.bytes() || format!("{:x}", hasher.finalize()) != source.file_sha256() { return Err(DataError::SourceMismatch); } Ok(framer.summary) } The raw source was selected independently before this read.
