The problem: changes need a fixed comparison point The previous chapter joined the tokenizer, decoder, training, evaluation, checkpoint and generation code. Now the course will extend that system. If the data, configuration and code change together, a changed result no longer tells you which version you observed. You need a fixed reference that identifies its inputs and states exactly what its checks establish. This chapter keeps the small scalar decoder unchanged. It gives that reference an input identity and a report whose claims stay attached to their evidence. The identity identifies the fixed inputs. The checks establish which behavior this execution reproduced. Neither establishes useful laptop-scale capability.
What the reference actually does The fixture assigns 8 documents to training, 2 to validation and 2 to test. The decoder has 1188 learned scalar parameters and context capacity 4 tokens. Its primary training schedule and separately executed replay each perform 32 updates on full batches of 16 windows, with 4 valid targets per window. Therefore, each schedule consumes 32\cdot16\cdot4=2048 valid training targets. One pipeline invocation includes both schedules: 4096 targets altogether. These counts are derived from the frozen full-batch schedule, not from a new runtime token counter. Evaluation targets and generated tokens are separate quantities. The report’s independent_schedules field counts two separately executed copies of the same schedule from training seed 39, not statistically independent seed samples. The replay agrees bit for bit with the primary training result in this execution. The selected decoder and frozen bigram then score the same 1744 overlapping test-window target slots. Their mean negative log-likelihoods are approximately 3.866087547 and 3.981342714 nats per slot, respectively. This known comparison is a regression check: rerunning it can expose changes in the checked behavior. It is not an independent estimate of generalization. There are only 442 within-document transition occurrences in those test documents. Overlapping windows repeat occurrences, so 1744 is not a count of distinct transitions. A separate policy would score each occurrence once, using the longest available causal prefix capped at four tokens and only its newest-position distribution. This run does not report numeric mean NLL or perplexity under that policy. The checkpoint round trip preserves its encoded bytes, model and optimizer bits, and tokenizer. The restored decoder reproduces logits for the fixed At probe, encoded as token IDs [67,118]. Cached and complete-prefix generation agree on token IDs [260,34,34]: Cyrillic т followed by two spaces. Agreement checks the two generation paths; those three tokens do not demonstrate useful language quality.
The solution: identify inputs, then interpret evidence R_{\mathrm{ref}}=\operatorname{SHA256}(\mathrm{config}_{1188}\Vert\mathrm{fixture}\Vert\mathrm{source\_revision})
The identity’s symbols and fixed settings R_{\mathrm{ref}} is a 256-bit digest, displayed as 64 lowercase hexadecimal characters. Its three named inputs are: \mathrm{config}_{1188}: a canonical record of eighteen tiny-run settings, together with the invariant that the decoder has 1188 parameters. \mathrm{fixture}: a canonical record of SHA-256 digests of the exact corpus bytes and exact split-manifest bytes. Even a byte change that leaves parsed JSON meaning unchanged creates a different input identity. \mathrm{source\_revision}: a verified source identity combining a baseline revision with the exact forty course-owned scalar-reference source files. Here \Vert means composition into the shared identity format’s named, canonical fields, not writing three unframed strings beside one another. That distinction matters: without field boundaries, different input sequences can have the same concatenated bytes. The helper orders fields, serializes one unambiguous record and hashes its complete bytes. The settings fix eight BPE merges; decoder width, feed-forward width and context capacity of four; one attention head and one block; stride one; training and evaluation batch sizes of sixteen and one hundred twenty-eight; thirty-two updates; learning rate 0.04; gradient-norm cap 1; training seed 39; generation seed 38; bigram smoothing 1; generation temperature 0.8; top-k four; and three generated tokens. The identity records floating-point settings by their exact bit patterns rather than rounded display text. It does not prove that the algorithm is correct or that a new machine will reproduce every floating-point bit. The source identity deliberately covers the forty scalar-reference source files, not this chapter’s reporting wrapper or interface. Toolchain, locked dependencies and arithmetic environment are recorded separately. A matching source digest is therefore not evidence that two execution environments match. The temporary checkpoint path is also outside the input identity; changing that path does not change the model’s fixed inputs. Likewise, exact checkpoint reload is narrower than complete job resumption. This check does not restore every data cursor, in-flight operation or whole-job continuation state. No laptop throughput is measured here.
History: reporting conditions and measuring variation A language-model score without its input conditions and scope does not identify what was evaluated or establish which capabilities were checked. Model Cards for Model Reporting was presented in 2019. Mitchell and colleagues propose model documentation that includes intended uses and evaluation conditions; a model card is not itself proof of quality. Model Cards describe evaluation conditions and intended uses; later fine-tuning experiments study variation across initializations and data orders. Reporting scope and measuring variation answer different questions. In Fine-Tuning Pretrained Language Models: Weight Initializations, Data Orders, and Early Stopping, published in 2020, Dodge and colleagues study fine-tuning variability associated with initialization and data order for pretrained language models. This does not measure variability in the course’s tiny decoder.
