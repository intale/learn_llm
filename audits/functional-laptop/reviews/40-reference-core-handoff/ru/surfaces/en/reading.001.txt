The problem: changes need a fixed comparison point The previous chapter joined the tokenizer, decoder, training, evaluation, checkpoint and generation code. Now the course will extend that system. If the data, configuration and code change together, a changed result no longer tells you which version you observed. You need a fixed reference that identifies its inputs and states exactly what its checks establish. This chapter keeps the small scalar decoder unchanged. It gives that reference an input identity and a report whose claims stay attached to their evidence. The identity identifies the fixed inputs. The checks establish which behavior this execution reproduced. Neither establishes useful laptop-scale capability.
