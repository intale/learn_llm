`forward_incremental` is the checked standalone entry: its caller supplies one attention layer, one input row, and one cache directly. Before calculating attention, it checks input rank and one-token shape, input batch and width, cache model width and head geometry, parameter-node identities and value revisions, the exact RoPE configuration, and remaining capacity, in that order. An arbitrary standalone caller could otherwise pair a valid input with an unrelated layer or cache.

After those checks, the crate-private `prepare_incremental_bound` wrapper creates one explicit `AutogradContext::no_grad()` for this standalone inference boundary and delegates to `prepare_incremental_bound_with_context`, the one shared calculation. A model-wide cache session can instead pass the no-gradient context that it selected before its embedding lookup into that same calculation.

The shared calculation passes its caller's immutable context through the $Q$, $K$, and $V$ projections, head splits, and RoPE rotations. The raw-tensor mixture computes numerically stable weights shaped $[B,H,1,t]$, where $t$ is the resulting one-based prefix length, and mixes the retained and candidate values. The function wraps that head output as an untracked constant, then passes the same context through the head merge and output projection. Each new autograd operation still performs its ordinary forward and finite-value checks, but it stores no reverse-mode parent edges. There is no ambient recording mode to enter, nest, or restore.

The function returns the complete output together with the candidate rotated key and unrotated value. Only a later commit copies those rows into the next cache slot and increments logical length.
