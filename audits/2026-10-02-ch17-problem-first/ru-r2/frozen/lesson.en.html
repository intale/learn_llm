Start trainable weights at a reproducible scale

Explain hidden-unit symmetry, choose a width-aware starting scale, and reproduce named trainable weights while separating sampled spread from expected linear variance.

In this chapter

Initialize named trainable matrices reproducibly at width-aware scales, distinguish hidden-unit symmetry from signal-scale drift, and explain the starting policies for biases, normalization gains, and token tables.

Quick reference

Start trainable weights at a reproducible scale

Chapter 17 terms for starting weight spread, equal-unit symmetry, and exact replay.

Fan-in
The count of input coordinates whose weighted contributions are summed into each output.
Fan-out
The count of output coordinates to which each input contributes.
Hidden-unit symmetry
Identical hidden units receive equal gradients under equal downstream treatment; equal updates keep them identical.
Parameter initialization
Assigning the trainable values from which later optimization starts.
Pseudorandom generator
A state-driven deterministic algorithm that supplies random-like draws, not cryptographic security.
Reproducibility
Recreating identical stored weights with the same implementation, generator state, request, and construction order.
Seed
The generator's raw starting state before its first draw; the same state gives the same continuation.
Target variance
The chosen spread of a weight distribution in squared weight units, not a finite matrix's measured spread.
Uniform bound
The endpoint magnitude of the zero-centered uniform interval used to sample weights.
Xavier-style initialization
Zero-centered sampling that balances forward and backward width effects under independence and near-linear assumptions.

A correct gradient still needs a useful starting point

Chapter 16 can differentiate a matrix transformation, but the backward pass cannot choose its initial weights. In a bias-free layer, two hidden units receiving the same input through the same activation compute the same feature when their incoming weight columns match. If the downstream calculation treats them equally, both receive the same gradient column. Applying equal updates then keeps the units identical: training has not given them separate features.

Weight scale is a second problem. Each matrix output adds contributions from several inputs, so changing the number of contributions can change the spread of the resulting signal. Repeating matrix transformations can compound that scale change. We need starting weights that distinguish the selected hidden units, account for matrix width, and can be reproduced while comparing changes to the model.

Let both matrix widths determine the starting spread

For the stored matrix WWW, weight WijW_{ij}Wij​ connects input coordinate iii to output coordinate jjj. Fan-in counts the weighted inputs summed into each output; fan-out counts the outputs receiving each input.

We estimate scale in a simplified setting: independent zero-centered dense weights with a common variance, independent zero-centered input features with a common variance, weight/input independence, and a symmetric activation near a unit-slope linear regime. The analogous backward estimate uses zero-centered arriving gradients with a common variance, independent of the weights.

Under these assumptions, the forward signal’s variance is multiplied by fan-in and weight variance. The backward gradient’s variance instead involves fan-out and weight variance. Keeping either multiplier at one asks for the reciprocal of its width; unequal widths ask for different scales.

Glorot/Xavier initialization uses this compromise:

Var⁡(Wij)=2fan⁡in+fan⁡out\operatorname{Var}(W_{ij})=\frac{2}{\operatorname{fan}_{in}+\operatorname{fan}_{out}}Var(Wij​)=fanin​+fanout​2​

The left side describes the target variance of the weight distribution, in squared weight units. It does not require the four displayed weights to have exactly that measured variance. The numerator balances the forward and backward requests; when both widths match, the same scale meets both idealized conditions.

To obtain weights of both signs at that spread, sample a zero-centered uniform distribution over [−a,a)[-a,a)[−a,a). Its variance is a2/3a^2/3a2/3, so matching the target gives a=6/(fan⁡in+fan⁡out)a=\sqrt{6/(\operatorname{fan}_{in}+\operatorname{fan}_{out})}a=6/(fanin​+fanout​)​. The standard deviation is the square root of the target variance. Standard deviation and bound are both in weight units, but the bound marks the interval endpoint rather than the typical spread around the mean.

SiLU does not exactly meet the activation assumption. Normalization, residual paths, data, and optimization also matter in the eventual decoder; the formula is not a decoder-wide variance-preservation theorem.

Turn the distribution into repeatable Rust samples

A bound alone does not choose individual weights. SplitMix64 supplies the repeatable draws. Its seed is the raw u64 state before the first increment, so seed zero is valid. Wrapping integer operations advance and mix that state. Dividing the integer in the high 53 mixed bits by the number of possible 53-bit values gives a binary64 fraction in [0,1)[0,1)[0,1). A fixed state gives the same continuation. This is deterministic pseudorandom sampling, not cryptographic randomness or ideal continuous sampling.

xavier_scale first rejects zero widths and an overflowing integer fan sum. It then stores the formula’s variance in target_variance, its square root in standard_deviation, and the sampling bound in uniform_limit. The sampler doubles a unit draw, subtracts one to center it, and multiplies by uniform_limit. One draw supplies each weight in row-major order, so the matrix shape fixes how many draws construction consumes.

The scale calculations and weights use f64. Integer checks happen before conversion, but a sufficiently large valid usize count can round when cast to f64. Division, square roots, and multiplication also use represented arithmetic. The generator’s finite grid and the stored values therefore differ from an ideal continuous distribution; printing twelve decimals rounds the stored value again. Bit-for-bit replay is an implementation result, not a claim that a finite matrix’s variance must equal the mathematical target. These small examples do not exercise floating-point underflow or overflow; the checked overflow errors concern integer dimensions.

Keep parameter construction replayable

A sampled matrix must become a trainable TensorValue leaf so later backward passes can accumulate its gradients. NamedParameter also gives that leaf a stable external name, such as decoder.block.0.attention.query.weight. The name identifies the parameter’s role across reconstruction; it is not the runtime node itself. Cloning a parameter shares its tape leaf, while constructing a new leaf with equal values does not.

Names need a fixed grammar and collections need duplicate rejection so name lookup cannot silently select an ambiguous parameter. Declaration order stays deliberate: on one shared generator stream, each successful construction consumes the draws that precede the next parameter. Inserting an earlier matrix changes the later samples.

A rejected request must not shift that stream. Name and width checks reject invalid requests before drawing, and checked dimension arithmetic prevents a wrapped storage count. Sampling uses a cloned trial generator; the caller’s state is committed only after tensor and trainable-leaf construction succeed. Every returned sampler error therefore leaves the caller’s state unchanged. Correcting a failed request can reuse its intended starting state.

The parameter kinds need not share one starting value. Our later decoder uses Xavier-style uniform matrix weights, optional zero biases, and RMSNorm gains of one. Zero biases add no initial offset, and unit gains apply no additional feature scaling after normalization. The token table reuses the sampler with vocabulary size and feature width as its shape inputs; that convention does not follow from a variance calculation for selecting a row.

From random word features to width-aware repeated projections

The earlier language-model example is Bengio et al., A Neural Probabilistic Language Model. Bengio et al. jointly train a word-feature matrix and neural matrices for next-word prediction. They report initializing the word features randomly, as for neural-network weights.

Random word features gave early neural language models trainable starting values, but randomness alone does not choose a scale for each matrix width. Bengio et al. do not specify a dimension-aware reproducible initialization rule; repeated transformations make that missing scale choice more consequential.

Glorot and Bengio connect starting weight variance to both forward and backward matrix widths under near-linear and independence assumptions. Transformers later combine learned embeddings with repeated attention and feed-forward projections, so many separately shaped trainable matrices need starting values.

The variance-aware analysis is Glorot and Bengio, Understanding the difficulty of training deep feedforward neural networks. Glorot and Bengio derive a compromise between fan-in and fan-out variance conditions under simplifying assumptions: target weight variance is 2 divided by the sum of the widths, implemented with a normalized zero-centered uniform distribution.

The later architecture is Vaswani et al., Attention Is All You Need. Vaswani et al. use learned embeddings and repeat query, key, value, attention-output, and two feed-forward projections in Transformer layers. Their paper does not prescribe a parameter initializer.

Our decoder uses reproducible Xavier-style uniform matrix samples, stable parameter names, zero optional biases, and RMSNorm gains of one. Its token table reuses the sampler by matrix shape. These are explicit construction policies: the Transformer paper does not prescribe them, and they do not guarantee exact variance preservation through SiLU, normalization, or residual paths.

The Transformer’s attention-score and embedding scaling act during forward computation; they are not instructions for choosing initial weights. Likewise, the papers do not define our raw-seed mapping, name grammar, construction order, or error policy. The Rust contrast below isolates an initialization failure condition without claiming to reproduce the historical models.

Inspect equal gradients and construction guarantees

The sampled projection avoids identical columns in the selected request. The zero-weight contrast shows why that distinction matters. Set x=[1,−1]x=[1,-1]x=[1,−1], use a zero [2,2] input matrix, apply SiLU, and combine the two hidden values with equal output weights [1,1]. Both hidden values and the scalar output are zero.

The reverse pass is seeded with one at that scalar output. Equal output weights give both hidden units the same upstream factor. SiLU’s derivative at zero is 1/21/21/2, and each input weight multiplies that factor by its input coordinate. Both gradient columns are therefore [0.5,−0.5]⊤[0.5,-0.5]^\top[0.5,−0.5]⊤, stored row-major as [0.5,0.5,-0.5,-0.5]. The backward pass produces a nonzero gradient, yet equal updates keep the two columns equal.

The condition is equal treatment, not simply the presence of a zero. Different downstream treatment would remove this particular equality argument. Zero optional biases and unit normalization gains are separate choices; they do not make unequal sampled feature columns identical.

Reject an invalid request without changing later draws

Valid names contain nonempty dot-separated segments of lowercase ASCII letters, digits, and underscores. The constructor checks the name first, then zero fan-in, zero fan-out, fan-sum overflow, shape-product overflow, storage reservation, tensor construction, and trainable-leaf construction. This order makes the first returned error stable when several inputs are invalid. The guarantee concerns returned errors; it does not promise recovery from every possible process allocation abort.

NamedParameter::from_tensor offers the same named trainable-leaf boundary for manually supplied finite values, checking the name before the leaf. NamedParameters::try_new scans declaration order and reports the earliest repeated name together with its first index; it does not sort or silently merge parameters.

The example constructs the query projection first and then the [4,2] token table on the continuing generator stream. A clone of the projection shares the original leaf. The independently replayed equal projection has the same values but a different runtime leaf.

Decoder.weight is rejected because its uppercase byte violates the name grammar. The valid name decoder.invalid.weight with zero fan-in instead returns ZeroFanIn. Collecting two projection clones repeats their name; duplicate rejection is a collection operation and consumes no draws. The example confirms that the rejected sampler calls leave the continuing generator state unchanged.

Separate measured weights from expected linear variance

Four weights make replay and unequal columns easy to inspect, but they do not show a distribution’s spread clearly. The figure uses three [64,64] matrices with 409640964096 weights each. The zero matrix uses no draws. The oversized matrix doubles every seed-17 Xavier weight, so the two uniform matrices have the same base draws and differ only in scale. Their different histograms therefore isolate the effect of the doubled bound.

All three populations use common equal-width bins. Each cell reports a count and its percentage of the complete matrix. The measured mean and population variance come from those finite weights: the calculation finds the mean first, then divides the sum of squared deviations by the weight count. A sampled mean need not be exactly zero, and the measured variance need not equal the target.

The depth table uses a different kind of evidence. It starts with independent zero-centered input features of common unit variance before any layer and follows expected signal variance through four independent linear layers using the target weight variances. Each layer has equal input and output widths and assumes independent zero-centered weights with a common variance, independent of its inputs. Doubling the Xavier bound gives four times the weight variance, so each such layer multiplies expected signal variance by four. Zero collapses the signal variance; equal-width Xavier keeps the expected variance at one. These entries are not measurements from a forward pass through the sampled matrices or guarantees for the nonlinear residual decoder.

Read the histogram as measured spread in one finite population and the depth table as an assumption-bound scale argument. Pairing the draws makes the scale comparison controlled; keeping the two kinds of variance separate prevents the picture from implying a decoder-wide theorem.

Give the initialized matrix token-lookup meaning

Initialization now supplies named trainable matrices with reproducible values and a declared starting scale. Chapter 18 turns a vocabulary-by-feature matrix into an embedding table: token IDs select rows, repeated occurrences of an ID reuse its row, and their gradients scatter-add. Passing vocabulary size and feature width to this sampler is our table-construction convention, not a variance derivation for row lookup.

One table is reused across batch items and sequence positions. That shared parameter identity is separate from the row selected by an individual token ID: different IDs select different rows, while repeated IDs share a row.

Keep construction order deliberate when several parameters share the initialization stream. Chapter 21 gives data shuffling a separately owned stream, Chapter 22 introduces optimizer state, and Chapter 35 persists parameter values and training provenance. The capability added here is reproducible construction of trainable leaves; token lookup and parameter updates are later operations.
