От обратного прохода в нейросетевой модели следующего слова к переиспользуемым VJP декодера

В модели Bengio и соавторов обучаемая таблица признаков слов, матричные преобразования и скрытый слой tanh задают вероятности следующего слова. Авторы явно выписывают формулы обратного прохода и обновления параметров именно для этой архитектуры. Такой разбор позволяет проследить весь процесс обучения. Однако лента из главы 15 пока описывает только структуру графа: в ней нет VJP для выбора строк, матричного умножения, нелинейности, нормализации и функции потерь по токенам, без которых нельзя обучить даже эту небольшую языковую модель.

Этот ранний подход с обучаемыми векторами признаков слов описан в работе Bengio et al., A Neural Probabilistic Language Model. Bengio и соавторы строят нейросетевую модель следующего слова из обучаемых строк признаков слов, матричных уравнений, скрытого слоя tanh, нормированных вероятностей на выходе и явной фазы обратного прохода и обновления параметров модели.

Расчёт выше повторяет наглядный стиль обратного прохода, выписанного специально для одной модели. Это новый пример на Rust, а не код, взятый из статьи или приписанный ей. Для добавления другой операции пришлось бы изменить весь обратный расчёт.

Abadi и соавторы описывают графы тензорных операций. При автоматическом дифференцировании система прослеживает все пути от функции потерь к каждому параметру и суммирует их вклады в градиент, в том числе для выбранных строк эмбеддингов. В Transformer Vaswani и соавторов обучаемые эмбеддинги находятся на входе, а выходная проекция — на выходе модели; матричные проекции, softmax внимания и нелинейные подсети прямого распространения повторяются в стеке слоёв. Позднее Shazeer исследует Swish при β=1\beta=1β=1 — то есть SiLU — и варианты SwiGLU в подсетях прямого распространения Transformer.

Переход к переиспользуемым графам операций описан в работе Abadi et al., TensorFlow: A System for Large-Scale Machine Learning. Abadi и соавторы представляют операции вершинами графа, а тензоры — значениями рёбер, описывают автоматическое дифференцирование, которое суммирует все обратные пути к параметру, и показывают графы эмбеддингов с операцией Gather, градиенты которой обновляют выбранные строки.

Расположение операций в Transformer описано в работе Vaswani et al., Attention Is All You Need. Vaswani и соавторы строят Transformer из обучаемых эмбеддингов, обучаемых проекций запросов, ключей и значений, softmax внимания, сетей прямого распространения с двумя преобразованиями и ReLU, а также обучаемого выходного преобразования, за которым следует softmax.

Следующий этап развития сетей прямого распространения показан в работе Shazeer, GLU Variants Improve Transformer. Shazeer определяет Swish как произведение входа на сигмоиду от βx\beta xβx; при β=1\beta=1β=1 получается функция SiLU. В работе она используется в вариантах SwiGLU для подсетей прямого распространения Transformer; для исследованных вариантов с вентильным механизмом автор сообщает меньший логарифм перплексии на отложенной выборке, чем у рассмотренной базовой модели. В исходной работе о Transformer используется ReLU; она не подтверждает, что Vaswani и соавторы применяли SiLU.

В этой главе добавляются переиспользуемые локальные VJP для пакетных матричных произведений, выбора строк по повторяющимся ID, exp⁡\expexp, log⁡\loglog, SiLU, устойчивого log-softmax и совмещённого вычисления среднего NLL по индексам целевых классов. Log-softmax и совмещённое вычисление среднего NLL по индексам целевых классов сохраняют для своих VJP значения вероятностей, полученные при собственном вызове прямого прохода, и не нормализуют логиты повторно. Эти операции образуют набор локальных правил обратного прохода для последующих компонентов эмбеддингов, проекций, SwiGLU, внимания и функции потерь по токенам. При обычном инференсе выполняется только прямой проход.

Сохраняйте данные прямого прохода, необходимые каждому локальному VJP

Публичные методы добавляют операции в ленту из главы 15, не создавая отдельный граф. TensorValue::gather_rows — публичная точка входа, которая проверяет аргументы выбора строк. Сначала лента проверяет, что операнд с таблицей ещё доступен. Если операнд доступен, метод по порядку проверяет следующие условия:

  1. таблица имеет ранг два;
  2. для index_shape можно без переполнения вычислить раскладку в порядке по строкам и число логических позиций;
  3. вычисленное число позиций равно indices.len(); и
  4. каждый ID при обходе в плоском порядке меньше числа строк таблицы.

Если встречается ID вне диапазона строк, метод сообщает его первую плоскую позицию. Только после выполнения всех четырёх условий метод добавляет ширину таблицы к index_shape и проверяет полученную форму выхода. В рассматриваемом примере форма таблицы [3,2], значение index_shape=[4] и ID [1,1,1,2] дают форму выхода [4,2].

После успешной проверки закрытый тип RowGatherPlan, доступный только внутри крейта, владеет копиями ID и их логической формы, а также хранит форму исходной таблицы, вычисленную форму выхода и число элементов выхода. Закрытые поля не позволяют пользователю публичного API создать план в обход перечисленных проверок. Сам факт существования плана означает, что размеры и ID уже проверены; однако выделение памяти под выходной буфер всё ещё может завершиться ошибкой.

Ядро, копирующее строки в прямом проходе, получает план, а не исходные ID и форму. Поэтому оно не повторяет проверку ранга таблицы, соответствия числа ID логической форме и попадания каждого ID в диапазон строк. Ядро создаёт отдельную копию каждой выбранной строки, поэтому результат не ссылается на память таблицы. После успешного копирования ID и формы из плана переходят в сохранённый контекст выбора строк. Ядро доверяет плану только в том смысле, что внутренний код мог создать этот план лишь после всех проверок. Публичный API по-прежнему не принимает непроверенные ID.

При обратном проходе через выбор строк создаётся нулевой тензор точной формы исходной таблицы. Для каждого плоского вхождения соответствующая входящая сопряжённая величина добавляется в строку, указанную сохранённым ID. Именно на этом шаге объединяются вклады вхождений с одинаковым ID: в прямом проходе для них создаются отдельные строки, но при обратном проходе их вклады могут попасть в одну строку исходной таблицы.

Остальные правила построены по тому же локальному принципу. VJP матричного умножения транспонируют последние две оси и суммируют вклады вдоль пакетных осей, расширенных при согласовании форм, чтобы восстановить исходную форму каждого родительского тензора. exp умножает входящую величину на сохранённый выход, log делит её на сохранённый положительный вход, а SiLU использует сохранённый вход и устойчиво вычисленное значение сигмоиды.

TensorValue::log_softmax выполняет один вызов прямого прохода с проверкой входных данных и получает два тензора: логарифмы вероятностей для вызывающего кода и обычные вероятности для VJP. После проверки входа один вызов обхода групп вычисляет для каждой группы один набор статистик и по этим данным формирует оба тензора. Операция сохраняет полученные значения вероятностей; при обратном проходе softmax повторно не вызывается и логиты заново не нормализуются.

TensorValue::indexed_mean_nll отдельно выполняет один вызов прямого прохода с проверкой входных данных для скалярного среднего NLL и вероятностей, необходимых VJP. Сначала лента подтверждает доступность операнда. После этого операция проверяет ось, число классов, число целевых индексов, непустой набор целей и каждый целевой индекс. Затем модуль вероятностей проверяет каждый логит на конечность и только после этого выделяет память под необязательный тензор вероятностей, сохраняя установленный порядок ошибок.

«Один вызов прямого прохода» не означает, что каждый логит читается один раз. Проверочный обход не вычисляет максимум, экспоненты, сумму или выход. Затем RowStats отдельно обходит классы для поиска максимума и для суммы сдвинутых экспонент. Обработчик группы использует эти данные, чтобы накопить скалярную функцию потерь, а код вывода ещё раз обходит классы и записывает тензор вероятностей для VJP. Сохранённый тензор содержит побитово те же значения f64, которые были сформированы при прямом проходе. Речь идёт о совпадении сохранённых чисел с плавающей запятой, а не о точных вещественных вероятностях. Все эти обходы относятся к одному вычислению нормализации, а не запускают нормализацию повторно.

Ветви log-softmax и среднего NLL по индексам целевых классов остаются двумя операциями. У каждой есть собственный результат и сохранённый контекст. Данные повторно используются между прямым проходом одной операции и её VJP, а не между двумя вызовами.

VJP для log-softmax вычитает из каждой входящей компоненты произведение сохранённой вероятности на сумму всех входящих компонент по оси классов. Пусть ggg — группа, ccc — класс, Zg,cZ_{g,c}Zg,c​ — входной логит, ygy_gyg​ — целевой класс, GGG — число групп, Pg,cP_{g,c}Pg,c​ — значение вероятности класса ccc в группе ggg, сохранённое при прямом проходе этой операции, а Lˉ\bar LLˉ — входящая скалярная сопряжённая величина. Тогда совмещённое вычисление среднего NLL по индексам целевых классов даёт сопряжённую величину логита по формуле

Zˉg,c=LˉG(Pg,c−𝟏[c=yg]).\bar Z_{g,c}=\frac{\bar L}{G}\left(P_{g,c}-\mathbf{1}[c=y_g]\right).Zˉg,c​=GLˉ​(Pg,c​−1[c=yg​]).

Для целевого класса из сохранённой вероятности в скобках вычитается единица. Затем все компоненты умножаются на общий множитель Lˉ/G\bar L/GLˉ/G: Lˉ\bar LLˉ передаёт входящую сопряжённую величину, а деление на GGG учитывает усреднение по группам.

Полный пример строит выбор строк, матричное умножение, SiLU, отдельную ветвь log-softmax и совмещённое вычисление функции потерь из значений выше, а затем сопоставляет тензоры прямого и обратного проходов с расчётом на заданных массивах. Здесь вызывается backward_with_trace, потому что для сопоставления нужны сопряжённые величины выходов SiLU, матричного умножения и выбора строк. При обычном обучении используется метод без трассировки: backward, если подходит поведение сохранения графа по умолчанию, или backward_with_seed, если сохранение либо освобождение графа нужно выбрать явно. Все эти методы выполняют один и тот же обратный расчёт. Трассировка лишь записывает результаты локальных VJP; сами производные повторно не вычисляются.

Каждый новый VJP сравнивается с центральными разностями в выбранных координатах. Оба родителя матричного умножения проверяются отдельно; для каждой из остальных операций — выбора строк, exp, log, SiLU, log-softmax и среднего NLL по индексам — также выбираются отдельные координаты.

Схема отделяет компактную цепочку прямого прохода от накопления при обратном проходе. После SiLU граф явно разветвляется на два отдельных вызова над одними и теми же логитами: log-softmax возвращает логарифмы вероятностей, а совмещённое вычисление среднего NLL — скалярную функцию потерь. Каждая операция сохраняет значения вероятностей, полученные при собственном вызове прямого прохода.
