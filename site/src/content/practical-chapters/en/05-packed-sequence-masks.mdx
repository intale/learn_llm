## The problem: shared storage can change context

Right padding preserves unequal examples, but short rows can leave unused
storage. Placing several short examples in one row can fill those cells. An
ordinary causal mask, however, lets each query use every earlier key in that
row. A later example would then receive the earlier example as additional
context. Shifting concatenated source documents would also create next-token
targets across their boundaries.

We need to preserve the examples while moving their storage. Sequence packing
places complete, already formed input-target pairs into shared rows. Each
occurrence keeps its own segment identity and local positions, so storage
adjacency creates neither an attention edge nor a new target.

The existing layout uses `0` for BOS and `1` for EOS. These arrays are controlled
valid-ID examples in the $266$-entry fixture vocabulary. Their token counts
are $4$, $3$ and $5$; their prediction lengths are $3$, $2$ and $4$. A selected
range supplies one fewer next-token pair than source tokens.

Form each pair before packing. A's final input `100` still predicts its own
EOS `1`; it does not predict B's BOS. Globally shifting the concatenated source
documents would add an EOS-to-BOS pair at each join. Those targets do not belong
to the examples we selected. An explicitly selected interior range follows the
same rule: retain its existing neighboring pairs without adding BOS or EOS.

### Fill only the current row

Capacity $6$ means six prediction pairs per storage row. Our next-fit policy
reads examples in their supplied order. A fills columns zero through two, B
fills columns three and four, and the last cell is padding. C does not fit in
that one remaining cell, so it starts a new row and leaves two padding cells.
The packer never revisits an earlier row, sorts by length or splits an example.

The two input rows are `[0,99,100,0,101,-1]` and
`[0,102,103,104,-1,-1]`. Their targets are `[99,100,1,101,1,-1]` and
`[102,103,104,1,-1,-1]`. The rectangle stores $12$ cells and contains $9$ real
targets. `PAD_CELL` is `-1`, a storage marker rather than a vocabulary ID.

A, B and C receive occurrence segment IDs `0`, `1` and `2`. The segment rows
are `[0,0,0,1,1,-1]` and `[2,2,2,2,-1,-1]`, with `NO_SEGMENT` also `-1`.
The position rows are `[0,1,2,0,1,0]` and `[0,1,2,3,0,0]`. B therefore begins
at local position zero even though its storage column is three. Padding's
stored position zero is unused.

An occurrence is one supplied use of an example. Two uses of the identical
source document and range still receive distinct occurrence ordinals and
segments. Their source IDs, example IDs and ranges may match; their causal
contexts remain separate.

Input validity, target validity and loss eligibility keep the meanings from
Chapter 4. Every real target is supervised here, so the three row-zero fields
are <code style="overflow-wrap: anywhere;">[true,true,true,true,true,false]</code>; the row-one fields are
<code style="overflow-wrap: anywhere;">[true,true,true,true,false,false]</code>. Input validity says an input exists, target
validity says its immediate successor exists, and loss eligibility says that
target is supervised. Their agreement in this fixture does not make the fields
interchangeable.

## Permission depends on the example

$$
M_{ij}=v_i v_j\mathbf{1}[s_i=s_j\land p_j\le p_i]
$$

The relation applies within one row. A query may use a key only when both
positions are valid, both belong to the same occurrence segment, and the key's
local position is no later than the query's. A binary value of one means
permitted; it is not an attention probability.

This is block-causal permission: the allowed entries form one causal block per
occurrence.

For B's first query, storage column three, the only permitted key is column
three. The earlier keys in columns zero through two belong to A and are
excluded. B's next query permits columns three and four. Merely checking that
the key precedes the query in storage would admit A incorrectly.

Both validity checks matter. Padding cells share segment `-1` and stored
position zero, so segment equality and local causality alone would allow
padding-to-padding edges. An inactive query instead skips softmax and produces
a zero attention mixture. A later bias or residual may produce a nonzero
padded hidden state; validity must prevent that state from influencing real
predictions or loss.

## What the permission symbols mean

<div id="packed-permission-symbols">

- $M_{ij}$ is binary permission for query column $i$ to use key column $j$
  within the same storage row.
- $i$ is the zero-based query column in that row.
- $j$ is the zero-based key column in that row.
- $v_i$ is query input validity: $1$ for a real input and $0$ for padding.
- $v_j$ is key input validity: $1$ for a real input and $0$ for padding.
- $s_i$ identifies the occurrence segment containing the query.
- $s_j$ identifies the occurrence segment containing the key.
- $p_i$ is the zero-based prediction position local to the query's occurrence.
- $p_j$ is the zero-based prediction position local to the key's occurrence.
- $\mathbf{1}$ is an indicator: $1$ when its bracketed condition holds and $0$
  otherwise.

</div>

For a contiguous segment, the allowed keys form an inclusive range from its
first storage column through the query column. B's segment starts at column
three, so its two ranges are `[3,4)` and `[3,5)` in Rust's half-open notation.
The checked start and valid length represent the permission relation without
allocating a separate dense mask for every row and attention head.

Position reset and segment isolation are separate requirements. Assigning B
row-global positions `[3,4]` violates its local-position metadata. It does not
necessarily change rotary attention scores: with fixed unrotated queries and
keys, a common offset applied to all their positions in an isolated segment
preserves ideal relative rotary dot products. We check the local positions
directly. Resetting positions alone also cannot exclude A's keys.

### Keep the same nine-target objective

Packing retains the raw loss sum and valid-target count from Chapter 4. The
token-weighted loss gives every eligible target equal weight and conditions on
its own permitted segment prefix. Specify gold
probability $1/2$ for all three A targets, $1/4$ for both B targets and $1/2$
for all four C targets. These are constructed loss-probe probabilities,
rather than model predictions.

The negative log likelihood sums are $3\ln2$, $4\ln2$ and $4\ln2$ nats.
Adding them and dividing once gives $11\ln2/9=(11/9)\ln2$ nats per valid
target, printed as `0.847180` by the probe. The rows contain five and four
targets: averaging their means equally would give $(6/5)\ln2$, printed as
`0.831777`. Averaging the three document means equally would give
$(4/3)\ln2$, printed as `0.924196`. Both change the weight assigned to
individual targets.

The finite-logit probe uses vocabulary size $V=266$. For desired gold
probability $0<q<1$, give each nongold class logit zero and the gold class
logit $z_y=\ln((V-1)q/(1-q))$. Softmax assigns gold probability $q$ in ideal
arithmetic. The Rust calculation uses `f64`, with rounding and the declared
comparison tolerance.

In ideal arithmetic, for eligible target $i$ and vocabulary class $c$, the mean-loss logit
derivative is $(p_{ic}-\mathbf{1}[c=y_i])/N$, where $p_{ic}$ is that class's
probability, $y_i$ is the gold class and $N$ is the total eligible-target count.
Here $i$ indexes eligible targets across all rows. Excluded logit cells have
zero contribution. The loss adapter skips them before target conversion or
arithmetic; multiplying an already computed NaN by zero would not exclude it
safely. Zero eligible targets is an error because the mean has no denominator.

## Extend the existing storage and decoder

`PackConfig` declares prediction capacity, maximum rows per model call, cell
capacity and metadata budget. `pack_examples` validates the existing
`SequenceExample` inputs and their shared binding, then assigns whole examples
to the current row. An oversized example fails instead of being silently split
or truncated. An exact fill creates no extra empty row, and the final model call
retains its actual smaller row count.

storage. The embedding gather excludes `PAD_CELL`, rotary lookup uses local
positions, and the decoder runs its existing blocks and tied vocabulary
projection. `loss_packed` reuses the existing eligible-row gather and indexed
NLL. Packing adds no tokenizer token, probability kernel or second decoder.

### Count storage and attention separately

For $B$ rows of width $T$, token storage has $BT$ cells, while dense attention
has $BT^2$ query-key score positions per head. A causal segment of prediction
length $l$ permits $l(l+1)/2$ semantic edges. A permission edge says which
relationship is legal; it does not say whether the implementation computes
other score positions before masking.

## History: packing and the cost of moving attention data

Rectangular Transformer training batches allocate padding to accommodate
unequal sequence lengths, leaving some stored positions without real tokens. The original
2021 version of
[Packing: Towards 2x NLP BERT Acceleration](https://arxiv.org/abs/2107.02027v1)
examines that problem. The authors study BERT pretraining and compare two deterministic methods based
on sequence-length histograms. Using multiple sequences in one sample requires
additional attention masking and a change to the masked-language-model loss.
Those methods and BERT results do not specify our input-order next-fit policy,
causal targets or decoder performance.

Later attention work addressed the cost of moving data during the attention
calculation. The 2022 version-two FlashAttention paper describes an exact,
IO-aware attention algorithm that uses tiling to reduce transfers between GPU
high-bandwidth memory and on-chip SRAM.
[FlashAttention, version 2](https://arxiv.org/abs/2205.14135v2)

Changing the computation order is a
different decision from deciding which examples may attend to one another.
Neither an execution tile nor shared storage permits a cross-segment edge.

The runnable Rust contrast counts padded and packed storage, then visits the
same permitted edge inventory in query order and in tiles of width two. Sorting
copies of the inventories checks that the traversal order retains the same
relationships. The tile traversal is an illustration; it implements neither
FlashAttention's numerical kernel nor its GPU memory strategy and provides no
timing benchmark.

For a causal decoder, packing preserves each example's prediction and attention
boundaries. A later attention execution strategy must preserve each example's
permitted context. The tiny Rust traversal illustrates edge ordering without
reproducing FlashAttention or establishing a speedup.

## Keep the example contract as decoder depth grows

Packed rows retain the same selected source pairs, occurrence-local causal
prefixes and token weighting as separate examples. The decoder consumes their
checked local positions and key ranges through its existing block loop.
The next chapter addresses deeper configurable decoder blocks. More layers
must retain these boundaries at every attention operation; depth does not
repair an incorrectly joined context or target.
