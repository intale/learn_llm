## Share retained keys and values while keeping separate queries

Cached generation retains earlier keys and values so the decoder can extend a
prefix without recomputing every earlier row. In ordinary multi-head attention,
each query head has its own learned key and value projections and its own cached
K/V lane. More heads therefore retain more key/value data at the same per-head
width. A group of query heads can instead read shared keys and values while
keeping its distinct learned queries.

There is also a separate choice about context: an attention row may read its
whole permitted causal prefix or only a recent part of that prefix. Sharing K/V
heads changes which learned lanes exist. A local window changes which sequence
cells those heads may read. We will make both choices explicit in the existing
attention and cache.

### Follow four query heads into two shared groups

The worked example starts with the four content tokens in `abcd`, without
document boundary tokens. Its constructed embedding rows have width $8$ and
first features $1,2,3,4$; their other features are zero. There are $4$ query
heads and $2$ shared key/value heads, with $2$ features per head. Query heads
$0$ and $1$ read KV head $0$; query heads $2$ and $3$ read KV head $1$.
The zero-based map is $[0,0,1,1]$.

For this example only, set the query and key projection weights to zero. Every
permitted scaled dot product is then zero, so softmax gives equal weight to
every permitted key. The two value-head sequences, in token order, are

$$
V_0=\begin{pmatrix}1&0\\2&0\\3&0\\4&0\end{pmatrix},
\qquad
V_1=\begin{pmatrix}0&10\\0&20\\0&30\\0&40\end{pmatrix}.
$$

The output projection is the identity, so merging the four head results leaves
their coordinates unchanged. At the last query cell, $t=3$, full causal
attention permits key cells $0,1,2,3$. Each query head assigns weights
$(1/4,1/4,1/4,1/4)$. The resulting head outputs are

$$
\begin{aligned}
z_{0,3}=z_{1,3}&=(2.5,0),\\
z_{2,3}=z_{3,3}&=(0,25).
\end{aligned}
$$

For example, the first shared value coordinate becomes
$(1+2+3+4)/4=2.5$. The Rust report's merged output is
`[2.5,0.0,2.5,0.0,0.0,25.0,0.0,25.0]`.

Now give the same attention layer a window of $2$ cells, including the current
cell. At $t=3$, only key cells $2$ and $3$ contribute. Each query head's
weights become $(0,0,1/2,1/2)$, giving

$$
\begin{aligned}
z_{0,3}=z_{1,3}&=(3.5,0),\\
z_{2,3}=z_{3,3}&=(0,35).
\end{aligned}
$$

The merged Rust output is now
`[3.5,0.0,3.5,0.0,0.0,35.0,0.0,35.0]`. Both cases share the same K/V
groups; the changed permitted keys explain the changed averages. Equal
probabilities across query heads come from the deliberately zero Q/K in this
fixture. With learned nonzero queries, heads reading the same keys and values
can assign different probabilities.

## Give each query head an explicit shared KV head

Let $D$ be model width, $H_q$ the positive query-head count and $H_{kv}$ the
positive key/value-head count. The per-head feature width is $d=D/H_q$.
Require $D$ to be divisible by $H_q$, $d$ to be positive and even for RoPE,
and $H_q$ to be divisible by $H_{kv}$. These conditions give whole feature
lanes, complete rotation pairs and equally sized query-head groups.

Each group has $r=H_q/H_{kv}$ adjacent query heads. Query head $h$, indexed
from zero, reads shared KV head $g(h)=\lfloor h/r\rfloor$. In the worked
example, $r=2$, so the first two queries use KV head $0$ and the next two
use KV head $1$.

With row-vector matrix conventions, the bias-free query and output matrices
$W_q,W_o$ each have shape $[D,D]$. The key and value matrices $W_k,W_v$
each have shape $[D,H_{kv}d]$. For $B$ batch rows and $T$ stored sequence
cells per row, splitting the projections gives

$$
\begin{aligned}
Q&:[B,H_q,T,d],\\
K,V&:[B,H_{kv},T,d].
\end{aligned}
$$

Here $B$ counts independent batch rows, $T$ counts cells including any storage
padding, and $d$ counts features per head. The worked example's projected keys
have shape $[1,2,4,2]$. RoPE rotates Q and K using their existing position
labels. It leaves V unchanged and does not change which head shares which K/V.

For one batch row, write $q_{h,t}$ and $k_{g(h),j}$ for the rotated query
and key vectors. Their score is

$$
a_{h,t,j}=\frac{\langle q_{h,t},k_{g(h),j}\rangle}{\sqrt d}.
$$

For the set $\mathcal A_t$ of permitted key cells, normalize this query's
scores only over that set and mix its shared values:

$$
\begin{aligned}
p_{h,t,j}&=\frac{\exp(a_{h,t,j})}
 {\sum_{u\in\mathcal A_t}\exp(a_{h,t,u})},\quad j\in\mathcal A_t,\\
z_{h,t}&=\sum_{j\in\mathcal A_t}p_{h,t,j}\,v_{g(h),j}.
\end{aligned}
$$

$j$ and $u$ index key cells; $p$ is a dimensionless attention probability;
$v$ is the unrotated value vector; $z$ is the resulting head vector. Excluded
cells have probability zero. Each query head performs its own normalization.
The formula states the ideal normalization; Rust reuses its existing stable
`softmax` on the permitted scores.
Concatenating all $H_q$ head results restores $D$ features, which pass through
the existing output projection $W_o$.

Ordinary multi-head attention (MHA) is the endpoint $H_{kv}=H_q$, with one
KV head per query head. Multi-query attention (MQA) is $H_{kv}=1$, with all
queries sharing one KV head. Intermediate sharing is grouped-query attention
(GQA). These are settings of this same attention path. Changing $H_{kv}$
changes learned matrix shapes; it is not a way to convert trained weights by
editing a setting alone.

### Intersect the window with the context already permitted

For batch row $b$, let $n_b$ count active cells and let $s_{b,t}$ be the
first key cell in query $t$'s existing permitted segment. An active query
satisfies $t<n_b$. Without a local window, its causal keys satisfy
$s_{b,t}\le j\le t$. A positive window length $w$ counts the current cell
and at most $w-1$ earlier cells. The head map and window rule are

$$
\begin{aligned}r&=H_q/H_{kv},\\g(h)&=\lfloor h/r\rfloor,\\\ell_{b,t}&=\max(s_{b,t},t-w+1),\\\mathcal A_{b,t}&=\{j:\ell_{b,t}\le j\le t<n_b\}.\end{aligned}
$$

$\ell_{b,t}$ is the intersected lower bound and $\mathcal A_{b,t}$ is the
permitted key set. The segment bound is nonnegative, so it also prevents a
negative mathematical lower bound near the start. Rust uses saturating
subtraction before the maximum. An active valid segment always includes its
self key, keeping its normalization set nonempty. A zero window is refused.
Inactive padded queries keep zero attention probabilities and outputs.

The window counts sequence cells, independently of the numerical RoPE labels.
For six active packed cells, the report contains

$$
\begin{aligned}
\text{segment starts}&=[0,0,2,2,2,5],\\
\text{window-two starts}&=[0,0,2,2,3,5],\\
\text{RoPE positions}&=[0,1,0,1,2,0].
\end{aligned}
$$

At cell $4$, the segment starts at $2$, but the window starts at $3$; only
keys $3$ and $4$ remain. At cell $5$, a new segment starts at $5$, so only
self remains. Reset RoPE labels do not join segments or change this count.
A window of $1$ permits only self; a sufficiently wide window recovers the
existing causal range. “No local window” still obeys the model's position and
cache capacity.

## Count learned weights and retained cache data separately

The four bias-free attention matrices contain

$$
N_{\mathrm{attn}}=2D^2+2D H_{kv}d
$$

learned scalars per layer: the first term counts Q and output weights, and
the second counts K and V. With $H_{kv}=H_q$, this becomes $4D^2$.
Other model parts, including norms, feed-forward layers and the single tied
text table, retain their own parameter counts.

Each layer's cache stores K and V with physical shape $[B,H_{kv},C,d]$,
where $C$ is sequence capacity. For $L$ layers of `f64` data, allocation
payload in bytes is

$$
M_{\mathrm{KV}}=2B L H_{kv} C d\times8.
$$

The factor $2$ counts K plus V; $8$ is bytes per `f64` scalar. If $u$ prefix
cells are occupied, replace $C$ by $u$ to count their logical payload. Both
counts exclude Rust objects, vectors and allocator overhead. At fixed other
axes and element type, the GQA-to-MHA payload ratio is $H_{kv}/H_q$.

The complete-model report uses $B=1$, $L=2$, $C=8$, $D=8$, $H_q=4$,
$d=2$ and $u=6$. Its six rows include two document boundary tokens, unlike
the four content-only rows in the worked example.

not establish a smaller full-training peak memory footprint or faster attention.
These counts describe numerical payload, not complete process RAM, throughput
or model quality.

## Relate shared heads to local context

Ordinary multi-head attention keeps a separate learned key/value projection and cached lane for every query head; restricting a row's direct context is a separate choice from sharing those lanes.

In [GQA, published at EMNLP 2023](https://aclanthology.org/2023.emnlp-main.298/),
Ainslie and colleagues describe one key head and one value head shared within
each query-head group. Their comparison places MQA at one group and MHA at one
group per query. For conversion from an existing multi-head checkpoint, they
separately describe averaging K/V projections and further pretraining. Our
initialized examples perform neither conversion nor that adaptation procedure;
changing the head count alone supplies no quality guarantee.

In the [Mistral 7B report, version 1 dated 10 October 2023](https://arxiv.org/abs/2310.06825v1),
Jiang and colleagues describe GQA with sliding-window attention and a rolling buffer that overwrites old KV entries.
Stacked layers can transmit older information through more recent hidden
states. Our window restricts
each layer's direct keys while retaining fixed-capacity all-prefix storage.
It does not implement that rolling buffer or the report's chunked prefill.

Grouped-query attention shares key/value heads within query-head groups, while sliding-window attention restricts the direct keys read by each layer.
Keep head sharing, direct-context eligibility and physical cache storage distinct when accounting for an autoregressive decoder.
The adjacent map, inclusive-self window and small CPU fixtures here are course
choices. They establish none of either paper's speed, training or quality
results.

### Save the attention semantics with the model

KV-head count and the optional window belong to semantic model settings.
The existing native settings and `PortableModel` preserve them through text
model restoration and tokenizer-independent backbone restoration. The text
model still restores one shared embedding/head table. Equal-head/no-window
defaults preserve earlier archive identities by omitting the optional fields.

Native exact training checkpoints also retain these settings. The older legacy
checkpoint encoding refuses unsupported nondefault attention settings instead
of silently dropping them. These are extensions of the existing composition
and persistence paths.

## Reproduce the report and use the saved model

From the repository root, with Docker and the existing course Docker setup
available, run the default CPU example. Its configuration, tokenizer and text
fixtures are included; no downloaded model or external corpus is required.

```bash
COURSE_CORPUS=false ./course run cargo run --offline --locked --quiet -p practical-ch18-grouped-query-attention-context
```

The JSON contains `worked_example`, `packed_window_example`,
`model_comparisons` and the initialized CPU `f64` scope. It prints the head map,
two observed mixtures, packed starts, all four storage rows and four
same-model full/cached comparisons. Every comparison reports
`compared_logits: 1548`, `max_abs_logit_error: 0.0` and
`within_tolerance: true`.

To save a file and load it in another Rust program, run this entire block from
the same repository-root working directory with the same Docker setup. One
Docker shell retains the file while each Rust program exits before the next
starts.

```bash
COURSE_CORPUS=false ./course run sh -c '
set -eu
mkdir -p tmp/ch18-attention-flow
cargo run --quiet --offline --locked -p practical-ch18-grouped-query-attention-context -- save --model tmp/ch18-attention-flow/grouped-window.safetensors
cargo run --quiet --offline --locked -p practical-ch15-save-load-resume-model -- infer --model tmp/ch18-attention-flow/grouped-window.safetensors --prompt ab --tokens 3
'
```

The save command reports `initialized_updates: 0`, `query_heads: 4`,
`kv_heads: 2` and `window: 2`. Both programs report the same `model_id`:
`234d9d80f5d63091842fbf7b3cef7ac867aefd20732853a1a463c5b594f3f1f2`.
Chapter 15's inference command loads the saved settings and weights and reports
`device: "cpu"`, `precision: "f64"`, `tied_alias: true`, $3256$ parameter
scalars and $20$ named parameter tensors. Generated IDs `[91,21,170]` map to
bytes `[89,19,168]`. These initialized-model outputs demonstrate loading and
generation; they establish neither useful prose nor UTF-8 validity.
Separate disposable `./course run` invocations would lose the saved file.

With the same repository-root working directory and Docker setup, run the
example's two library tests:

```bash
COURSE_CORPUS=false ./course run cargo test --offline --locked -p practical-ch18-grouped-query-attention-context --lib
```

Both tests pass. The first checks the explained mixtures and full/cached
comparisons. The second performs actual accumulated training with shared heads
and window $2$, saves after one completed update, restores the existing native
checkpoint and checks agreement after both jobs reach update $2$. That training
test is separate from the zero-update default and saved inference example.

## Keep attention semantics with the same model

The text encoder, source-independent backbone, tied head and CPU inference
path now preserve shared K/V heads and a local context window. Separate query
calculations read compact shared cache lanes, while the window intersects the
keys each layer may use. The same-weight full/cached comparison checks those
choices together within the existing position and cache capacity.

The full reference still materializes repeated K/V lanes and dense scores.
Planned Chapter 19, Online and tiled attention, will study running normalization
and tiles for those attention intermediates. It is a separate planned extension
from the sharing and direct-context masks implemented here.
