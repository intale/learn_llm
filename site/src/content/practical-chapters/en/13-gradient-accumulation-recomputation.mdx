## The problem: one training update can retain too much

A training forward pass keeps values that reverse mode will need to calculate
gradients. More batch rows, longer sequences and more decoder blocks increase
the amount retained. Parameters and AdamW state also occupy memory, but reducing
the saved forward values addresses a different part of the problem.

Two choices help at different points. **Gradient accumulation** processes a
chosen logical batch in smaller microbatches, adds their gradients and delays
the optimizer until every contribution is ready. Each microbatch's graph can
then be released before the next forward pass. **Activation recomputation**
keeps block boundaries and reconstructs block interiors during backward,
exchanging retained values for extra forward calculations. Both choices must
preserve the loss whose gradient the optimizer receives.

First consider a small constructed loss example. One microbatch contains $2$
valid next-token targets with mean loss $1$; another contains $4$ with mean loss
$3$. Their loss sums are $2$ and $12$. The combined mean is therefore
$14/6=7/3$. Averaging the two means equally would give $2$, because it would give
the smaller microbatch's targets more weight. Padded positions do not add
targets to that denominator.

The decoder experiment uses three checked text examples containing $2$, $4$
and $3$ valid targets: $9$ in all. With the default maximum of two rows per
microbatch, their token grids have shapes $[2,4]$ and $[1,3]$, where the axes
count rows and supplied positions per row. The first microbatch contains $6$
valid targets and the final one contains $3$. Its final row count is smaller,
but every real target still belongs to the same logical update.

The full-batch and accumulated runs start from matching seed-$39$ models with
three decoder blocks, residual width $4$, one attention head and feed-forward
width $8$. They use the existing text encoder and tied text head, with $29$
named parameter tensors and $1572$ learned scalars. Dropout is disabled for
this comparison so that changing the grouping does not change random masks.

## Weight each mean by the targets it represents

Let $K$ count the microbatches in one logical update and let $i$ index them from
$1$ through $K$. Microbatch $i$ has $n_i>0$ valid targets and scalar mean
negative log likelihood $L_i$. Let $N$ be the total target count and $L$ the
mean over that total. All forwards use the same parameters $\theta$, held
fixed until the update. Hold the finite positive loss scale $S$ fixed as well.
Then, in exact arithmetic,

$$
\begin{aligned}
N&=\sum_{i=1}^{K}n_i,\\
L&=\sum_{i=1}^{K}\frac{n_i}{N}L_i,\\
\widetilde g&=\sum_{i=1}^{K}\nabla_\theta\!\left(S\frac{n_i}{N}L_i\right),\\
g&=\widetilde g/S.
\end{aligned}
$$

Here $\nabla_\theta$ takes the derivative with respect to the model parameters.
$\widetilde g$ is the accumulated scaled gradient, and $g$ is its unscaled
value before clipping. The target counts do not depend on the parameters, so
linearity of differentiation gives the gradient of the combined mean when
each microbatch represents the same per-example objective. Padding contributes
to neither $n_i$ nor $N$.

Reverse mode can multiply a scalar loss gradient by choosing its starting
seed. With $S=128$, the recorded `f64` seed for the first microbatch's target
share $6/9$ is $85.33333333333333$; the final microbatch's share $3/9$ uses
$42.666666666666664$. Each backward adds its contribution to the original
parameter leaves. The optimizer has not
changed those leaves' values between the two passes.

After all contributions succeed, divide by $S$, measure the global gradient
norm, apply the existing norm clipping and call AdamW once. Count the tied
input/output table once in that global norm. AdamW's moments, decoupled weight
decay and step advance belong to that one update; clipping each microbatch
separately would generally change the resulting gradient. Finally clear the
gradients and make one loss-scale growth decision.

In the measured CPU `f64` comparison, both groupings have mean loss
$5.622831723383019$ and global gradient norm $0.9389921230306614$.
The norm limit is $1$, so neither run clips. Both commit optimizer step $1$,
clear gradients and change the scale from $128$ to $256$ because this fixture
uses a growth interval of one committed update.

The comparison checks every coordinate of all $29$ scaled gradient tensors
and the updated weights. For reference coordinate $r$ and compared coordinate
$x$, it requires $|x-r|\le 10^{-11}+10^{-10}|r|$. The maximum observed absolute
scaled-gradient error is $1.7763568394002505\times10^{-15}$; the maximum weight
error is $3.469446951953614\times10^{-18}$. These observations support the
declared tolerance for this fixture, rather than bitwise equality for arbitrary
groupings or backends.

## Reconstruct the same block before differentiating it

Accumulation shortens the lifetime of each microbatch's graph. Within a graph,
ordinary training still retains each decoder block's intermediate values and
saved derivative contexts. A block activation checkpoint replaces that
interior tape with enough information to run the same block again.

With graph recording enabled, the initial checkpointed block forward uses a
no-grad context under the selected executor. After obtaining the block output,
it drops the interior tensors and retains the input boundary, aliases to the
original parameters, their revisions, the exact layout and positions, the
execution session and precision, and a block recipe. The recipe also retains
fixed rotary-position tables and compact tickets for the block's two dropout
sites. A parameter alias refers to the original learned node; it does not copy
another set of learned weights. Text lookup and the tied text head remain
outside these block checkpoints.

At backward time, the reverse engine first checks the original operand
revisions. It recreates the block from a fresh tracked boundary leaf with the
same parameter nodes, layout, execution and tickets. It checks the output's
shape and `f64` bits against the original block output before calculating the
block's local derivatives. Those derivatives provide a contribution for the
input boundary and for each block parameter. The local calculation does not
write gradients to the original parameters; the complete outer reverse pass
stages and checks all contributions before committing leaf gradients. A
successful releasing backward clears the checkpoint recipes and edges.

Dropout replay is essential to reconstructing that same computation. The
separate recomputation experiment keeps the layout
$[B,T,D]=[3,4,4]$, with $B$ batch rows, $T$ positions per row and $D$ residual
features. At dropout probability $0.5$ and seed $39$, the three blocks use six
sites. Each site consumes $48$ counter words, including padded positions.
Their consecutive counter ranges are $[0,48)$, $[48,96)$, $[96,144)$,
$[144,192)$, $[192,240)$ and $[240,288)$.

The compact tickets reproduce all six original masks. Reverse replay receives
no live random counter, so it leaves the live counter at $288$ after backward.
A seed alone would not provide this guarantee after repartitioning: changing
microbatch shape or padding changes the existing counter assignment to sites.
That is why the dropout replay comparison keeps the layout fixed and remains
separate from the accumulation comparison.

The retained and recomputed dropout runs have bit-identical forward logits.
Their measured maximum scaled-gradient and updated-weight errors are both
$0$ in this fixture. Both have mean loss $5.535604128733965$ and global norm
$1.4853618224483591$, clipped to $1$ before their one AdamW update. Each clears
gradients and advances the scale from $128$ to $256$. Reconstructing the three
blocks performs three extra block forwards during backward. These are bounded
observations, with no universal bitwise or speed claim.

### Measure what remains after forward

The observation point is completion of the loss forward, before backward.
For the tape reachable from the scalar mean-loss node,
`retained_tape_storage` counts unique nonparameter node primals,
the tensor payload of each edge's saved context, and the fixed rotary-position
tensors captured by checkpoint recipes. A primal is a stored forward value;
a saved context holds values needed by a local derivative. Multiplying their
`f64` value counts by $8$ gives the reported bytes.

For the fixed-layout dropout experiment, ordinary retention keeps $16808$
nonparameter primal values and $9736$ saved-context values: $212352$ bytes.
Recomputation keeps $10241$ primal values, $3751$ saved-context values and
$102$ fixed recipe values: $112752$ bytes. The last count includes, per block,
$2$ inverse frequencies, $16$ cosines and $16$ sines, for $816$ recipe bytes
across three blocks. The reachable tape has $210$ nodes ordinarily and $48$
with recomputation, including its three checkpoint nodes.

Saved contexts count any copied parameter primals they own. The observation
excludes the original master-parameter buffers, gradient and optimizer buffers,
Rust metadata, layout vectors, tickets, allocation capacity and transient
forward or reverse work. It therefore measures **retained tensor payload at
this point**, not total training memory, process memory, a peak or GPU storage.
The added backward work can have a different temporary lifetime from the
values counted here.

## Trade retained activations for repeated computation

Keeping every intermediate available for backward consumes more retained
tensor storage as decoder batches, sequences and depth grow. Chen and
colleagues' 2016 paper,
[Training Deep Nets with Sublinear Memory Cost](https://arxiv.org/abs/1604.06174v2),
presents a computation-versus-memory tradeoff by recomputing intermediate
activations. The useful intuition is to retain selected boundaries and
reconstruct what backward needs between them. Repeating whole blocks also
repeats forward work.

Selective recomputation chooses which intermediate calculations to repeat
instead of recomputing every operation in a block. Korthikanti and colleagues'
2022 paper,
[Reducing Activation Recomputation in Large Transformer Models](https://arxiv.org/abs/2205.05198v1),
studies selective recomputation and sequence parallelism to reduce unnecessary
recomputation in large transformer language-model training. Transformer training
must preserve each block's parameters, layout and random choices when
reconstructing the values needed for its gradients.

We retain block boundaries and repeat the existing block
computation during backward, while accumulating token-weighted microbatch
gradients before one shared optimizer update. The Rust example implements
bounded whole-block recomputation. Its retained-payload observation and
extra-forward count do not reproduce either paper's schedules, parallelism or
performance results.

## Extend the existing update and reverse owners

`decoder_update_with_accumulation` accepts a checked `VariableBatchEpoch` as
the explicit group for one logical update. The caller chooses that group;
the type's name does not add whole-dataset scheduling. The entry requires
training batches, positive checked target counts and cleared model gradients.
The total must be at most $2^{53}$ so its integer count converts exactly to
`f64`. Each callback returns the existing `MaskedLoss` with the checked batch's
target count.

The entry seeds each mean backward with its scaled target share, releases that
graph and accumulates gradients owned by the same parameter leaves. After the
last microbatch, `finish_decoder_update` performs the shared unscale, global
clipping, AdamW and gradient clearing. The loss-scale controller advances only
after that successful logical update.

### Discard a failed partial logical update

An earlier microbatch may have finished backward when a later one fails.
The accumulation owner clears those partial model gradients before returning
a forward, observer or reverse failure. A numerical overflow in local backward
or gradient addition returns `Skipped` and backs off the loss scale; structural
errors propagate as errors. Neither case applies AdamW before the shared finish
phase. Arbitrary effects inside caller callbacks and advancement of a live RNG
are outside this cleanup; a retry that needs identical randomness must restore
caller-owned RNG state or use replay.

The overflow example first commits a warm-up so AdamW already has moments.
For the second microbatch of the next attempted update, it substitutes a
constructed zero-logit branch multiplied by `f64::MAX`. Forward remains finite,
but backward becomes nonfinite. One microbatch's model gradients have already
accumulated. The skip clears them and preserves the original zero-gradient bits,
weight bits and revisions, AdamW moments and beta powers, and optimizer step
$1$. Scale changes from $128$ to $64$. Scheduled step $2$ remains available to
the caller; this example records that eligibility without performing a retry.
An AdamW step with zero gradients can still apply weight decay and advance
optimizer state; the skipped attempt does neither.
The injection is a failure probe rather than ordinary model logits.

## Carry one logical update into schedule reasoning

The existing text encoder, source-independent transformer, tied head, reverse
engine and AdamW now support token-weighted logical updates and per-block
activation recomputation. Accumulation controls when gradients combine and the
optimizer acts; recomputation controls which block values remain between
forward and backward. Both preserve the existing component boundaries and use
text as the worked input.

Chapter 14 will extend schedule and clipping reasoning around this existing
update owner, including warmup and decay. Global clipping already exists and
is reused here. Chapter 15 will address portable model saving and loading and
the additional state needed for training continuation. An activation checkpoint
is a temporary differentiation recipe, not a durable file of learned weights.
Full-corpus training, physical-GPU measurements and accelerated mixed-precision
