## Keep a summary instead of the whole attention grid

The dense reference computes a score and a probability for every query-key
coordinate. With twice as many sequence cells, each of those stored grids has
four times as many values. Sharing K/V heads reduces the learned and cached
K/V lanes; a local window restricts eligible keys. Neither change automatically
removes the dense grids from that reference implementation.

An attention output needs the normalized weighted sum of values. It need not
retain every weight at once. We can consume keys and values in tiles, carrying
a score maximum, a normalization sum and a weighted value vector from one tile
to the next. Rescaling the two sums when the maximum changes preserves the
relative weight of earlier keys.

### Follow the last query through two tiles

The content-only text `abcd` supplies four constructed feature rows at sequence
cells $0,1,2,3$. There is one query/key feature and two value features per row:

$$
Q=\begin{pmatrix}1\\1\\1\\1\end{pmatrix},\qquad
K=\begin{pmatrix}0\\1\\2\\3\end{pmatrix},\qquad
V=\begin{pmatrix}1&10\\2&20\\3&30\\4&40\end{pmatrix}.
$$

Row $j$ of $K$ and $V$ belongs to the same text cell. The final query cell
is $3$, whose query vector is $(1)$. Dividing its dot products with the four
keys by $\sqrt{1}=1$ gives scores $(0,1,2,3)$. All four keys are causally
eligible for that query. This raw attention example is separate from the
configured RoPE decoder: its key width
is $1$ and its value width is $2$, whereas the decoder's rotary head width
remains even.

Use query and key tile edges of $2$ cells. For the final query, the first key
tile contains keys $0,1$. Subtracting its maximum $1$ gives exponential weights
$\exp(-1)$ and $1$. The state after this tile is

$$
\begin{aligned}
m&=1,\qquad \ell=\exp(-1)+1\approx1.367879,\\
u&=\bigl(\exp(-1)+2,\;10\exp(-1)+20\bigr)\\
 &\approx(2.367879,23.678794).
\end{aligned}
$$

Here $\ell$ is the shifted exponential sum, and the two coordinates of $u$
are the corresponding unnormalized weighted value sums. The second tile
contains keys $2,3$, so the maximum rises to $3$. Earlier weights were measured
relative to $1$; they must now be measured relative to $3$. Multiply both
previous sums by $\alpha=\exp(1-3)\approx0.135335$, then add the new keys.
Primes below mark the updated sums:

$$
\begin{aligned}
\ell'&=\alpha\ell+\exp(-1)+1\approx1.553002,\\
u'&=\alpha u+\exp(-1)(3,30)+(4,40)\\
  &\approx(5.424096,54.240960).
\end{aligned}
$$

Only after the final tile do we divide each weighted-sum coordinate by the
normalizer. The result is approximately $(3.492653,34.926527)$. Rust reports
tiled output <code style="overflow-wrap: anywhere; white-space: normal;">[3.492652734585769,34.9265273458577]</code> and dense output
<code style="overflow-wrap: anywhere; white-space: normal;">[3.49265273458577,34.92652734585769]</code> for this row. Across all $8$ output
coordinates, the maximum absolute difference is
$7.105427357601002\times10^{-15}$, within the declared CPU `f64` absolute
tolerance $10^{-10}$.

## Rescale earlier mass before adding a new tile

Fix one active query vector $q$ with $d$ features. Key vector $k_j$ has the
same positive feature count $d$; $j$ is its zero-based sequence-cell index.
Their dimensionless score is $s_j=\langle q,k_j\rangle/\sqrt d$. Value vector
$v_j$ has $d_v$ features, which may differ from $d$ in raw attention.

Let $J$ be the nonempty set of eligible keys in the current tile and $a$ its
largest score. Before the tile, $m$ is the maximum score seen, $\ell$ is the
sum of exponential weights shifted by $m$, and $u$ is their weighted value
sum. Start with $m=-\infty$, $\ell=0$ and the zero vector $u$. A prime marks
the updated state. The complete rule is

$$
\begin{aligned}s_j&=\langle q,k_j\rangle/\sqrt d,\\a&=\max_{j\in J}s_j,\quad m'=\max(m,a),\\\alpha&=\exp(m-m'),\quad p_j=\exp(s_j-m'),\\\ell'&=\alpha\ell+\sum_{j\in J}p_j,\\u'&=\alpha u+\sum_{j\in J}p_jv_j,\\o&=u/\ell.\end{aligned}
$$

The factor $\alpha$ converts the previous sums to the new maximum. Each
$p_j$ is an unnormalized shifted exponential, not a final probability.
$\ell'$ is dimensionless and positive after a contributing tile; $u'$ and
the final output $o$ have $d_v$ value coordinates. The last line uses the
completed sums after all eligible tiles. Rust explicitly uses $\alpha=0$
for the first contributing tile.

For any already consumed key, the identity
$\exp(s_j-m)\exp(m-m')=\exp(s_j-m')$ explains why rescaling preserves its
relative mass. Applying the same factor to $u$ preserves its contribution to
every output coordinate. Independently normalizing each tile and averaging
its output would lose the relative normalization mass of the tiles.

A tile with no eligible keys leaves all three state values unchanged. It
does not compute $-\infty-(-\infty)$. Existing valid causal layouts include
self for each active query, so its final normalizer is positive. Inactive
padded query rows remain zero and undergo no division.

Finite inputs also do not guarantee representable dot products or weighted
sums; the operation refuses nonfinite results rather than returning a partial

## Reconstruct probabilities when a gradient needs them

For zero-based query-row index $i$, retain its output vector $o_i$, final
maximum $m_i$ and positive normalizer $\ell_i$. During backward, let $g_i$ be the upstream
gradient with respect to $o_i$; it has the same $d_v$ coordinates. Recompute
scores from the saved query and key vectors, then reconstruct the eligible
probabilities:

$$
P_{ij}=\frac{\exp(s_{ij}-m_i)}{\ell_i}.
$$

$s_{ij}$ is the scaled score of query $i$ and key $j$; $P_{ij}$ is its
dimensionless normalized probability. Masked coordinates have probability
zero. For a scalar objective $L$, use the prefix $\mathrm d$ to denote a
gradient of $L$ with respect to the following quantity. Define

$$
\begin{aligned}
D_i&=\langle g_i,o_i\rangle,\\
\mathrm dP_{ij}&=\langle g_i,v_j\rangle,\\
\mathrm dS_{ij}&=P_{ij}(\mathrm dP_{ij}-D_i).
\end{aligned}
$$

$D_i$ is one scalar per query row. $\mathrm dP_{ij}$ measures how the
objective changes with that probability; $\mathrm dS_{ij}$ measures how it
changes with the score. The softmax correction subtracts the row-wide
weighted mean $D_i=\sum_jP_{ij}\mathrm dP_{ij}$, which can be obtained from
the already saved output instead of storing a probability row.

For a query/key tile, $Q$ and $K$ hold its row vectors, $V$ holds its value
rows, and $G$ holds its upstream vectors. Matrices $P$, $\mathrm dP$ and
$\mathrm dS$ have query rows and key columns. Accumulate

$$
\begin{aligned}
\mathrm dQ&\mathrel{+}=\mathrm dS K/\sqrt d,\\
\mathrm dK&\mathrel{+}=\mathrm dS^{\mathsf T}Q/\sqrt d,\\
\mathrm dV&\mathrel{+}=P^{\mathsf T}G.
\end{aligned}
$$

The superscript $\mathsf T$ transposes the tile. These gradients have the
same shapes as their corresponding $Q$, $K$ and $V$ inputs. Excluded keys
contribute zero. When several query heads read one shared K/V head, their
key and value gradients add into that same shared head.

## Separate running summaries from GPU memory movement

Materialized attention stores a score and a probability for every query-key coordinate, so these intermediate grids grow quadratically with sequence length even though the output is a vector per query.
This familiar reference makes every weight inspectable, but retaining those
grids is an implementation choice rather than a requirement of the output.

In [Online normalizer calculation for softmax, version 1 dated 8 May 2018](https://arxiv.org/abs/1805.02867v1),
Milakov and Gimelshein's Algorithm 3 updates a running maximum and rescales the previous exponential normalizer when that maximum changes.
That paper's normalizer supplies the scalar part of the recurrence; our
attention calculation also carries a weighted value vector.

[Rabe and Staats's attention paper](https://arxiv.org/abs/2112.05682v3)
was initially released in 2021; the cited version 3 is dated 10 October 2022.
Rabe and Staats describe stable weighted attention summaries, query/key chunking and recomputation of chunk intermediates during differentiation.
Saving every intermediate summary for ordinary automatic differentiation
would lose the intended storage saving, so their account makes recomputation
part of the solution.

In [FlashAttention, version 1 dated 27 May 2022](https://arxiv.org/abs/2205.14135v1),
Dao and colleagues combine tiling, recomputation and fused GPU execution to reduce attention reads and writes between high-bandwidth memory and on-chip SRAM.
That memory hierarchy and fused kernel are additional implementation choices;
the course's host-backed primitive calls do not reproduce them. The cited
Rabe/Staats revision is later than this FlashAttention edition.

Stable running summaries allow attention to consume key/value tiles; reconstructing probabilities during backward avoids retaining their complete grid.
Keep the existing dense attention as an inspectable reference and add output-oriented tiled evaluation through the same projections, layouts, tensor executor and autodiff tape.
Evaluate the same decoder attention with smaller explicit intermediate buffers while keeping logical storage, GPU memory traffic and measured speed as separate claims.
The course implements host-backed tiled attention and reports bounded CPU `f64` comparisons and logical payload counts. It does not reproduce a fused FlashAttention kernel or measure GPU traffic, speed or language quality.

</div>

## Change attention evaluation inside the existing model

The raw operation accepts $Q:[B,H_q,T,d]$, $K:[B,H_{kv},T,d]$ and
$V:[B,H_{kv},T,d_v]$, producing $[B,H_q,T,d_v]$. Here $B$ counts batch
rows, $T$ counts stored sequence cells, $H_q$ counts query heads and
$H_{kv}$ counts shared key heads and, separately, value heads. Feature counts
$d,d_v$ are positive, as are the head counts, and $H_q$ must be divisible by
$H_{kv}$. Chapter 18's adjacent group map selects the same shared head in
the dense layer, tiled forward and tiled backward. Compact K/V stay
unexpanded.

Common preparation still performs the learned projections, rotates $Q,K$ with
RoPE, leaves $V$ unrotated and intersects the causal range with active lengths,
packed-segment boundaries and any local window. The resulting interval determines which entries contribute to each query's
attention sum; the implementation still reads and scores rectangular prefix
tiles that can include excluded entries, then sets their weights to zero before
the weighted value product. Sequence-row indices remain distinct from RoPE labels.
Tiles change neither the direct causal context nor cache capacity or eviction.
Head outputs still merge and pass through the existing output projection.

## Reproduce the report and inspect its checks

Run from the repository root with Docker and the existing course Docker
setup available. All configuration, tokenizer and text fixtures are included;
no downloaded model or external corpus is needed. The default CPU command is

```bash
COURSE_CORPUS=false ./course run cargo run --quiet --offline --locked -p practical-ch19-online-tiled-attention
```

It prints JSON with `worked_example`, `gradient_comparison`,
`storage_comparisons` and `model_comparison`. It reports `Cpu`, `f64`, tile
edges $2/2$ and `within_tolerance: true` for every comparison. The two
successive summaries are in `worked_example.tile_summaries`.

From the same working directory and Docker setup, run the two demo tests:

```bash
COURSE_CORPUS=false ./course run cargo test --offline --locked -p practical-ch19-online-tiled-attention --lib
```

Exactly $2$ tests pass: the report checks and the actual accumulated-training
continuation through update $2$. To run the small attention-kernel checks

Exactly $8$ tests pass, including the exhaustive small-coordinate finite

  <li id="online-tiled-attention-answer-1" data-review-id="online-tiled-attention-answer-1">The maximum changes from $1$ to $3$, so $\exp(-2)$ converts the previous normalizer and weighted value vector to the new score scale. The completed sums are divided only once. Tile outputs normalized separately omit their different relative masses; an unweighted average is not the full attention result.</li>
  <li id="online-tiled-attention-answer-2" data-review-id="online-tiled-attention-answer-2">At $T=8,16,32$, each dense grid contains $256,1024,4096$ values, while the largest score tile has $4$ values, or $32$ bytes. Five counted temporary forward buffers contain $20$ values, or $160$ bytes. Inputs contain $128,256,512$ values; output and combined row statistics each contain $64,128,256$. Each value occupies $8$ bytes. These selected payloads exclude overhead and other workspaces, so they establish neither peak process RAM nor speed.</li>
  <li id="online-tiled-attention-answer-3" data-review-id="online-tiled-attention-answer-3">The report compares $4$ query, $4$ key and $8$ value gradient coordinates with dense attention; all errors are within $10^{-10}$. The kernel command selects and passes $8$ tests.</li>

## Keep the model while changing its intermediate work

The existing text encoder, source-independent backbone, tied head and trainer
can now evaluate attention with compact shared heads and reconstructed
gradients. Running summaries replace complete intermediate score/probability
grids in the output-oriented path while the dense reference remains available
for inspection. Eligible keys and learned projections keep their existing
meaning.

Planned Chapter 20, Paged KV layout, will study logical-to-physical cache
pages and partial-page waste while preserving cached logits. That future
storage layout is separate from this chapter's attention tiles; no page
allocator, serving scheduler or multi-tenant cache is introduced here.
