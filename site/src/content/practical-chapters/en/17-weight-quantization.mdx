## Spend fewer saved bytes on each weight

The model saved in Chapter 15 stores each learned weight as an `f64`, using
$8$ bytes per value. Many nearby weight values can instead share a small set
of representable levels. Saving an integer level number and a scale can reduce
the weight payload, but reconstructing a level generally changes the weight.
Those changes can alter matrix products, token probabilities and generated
tokens. A useful comparison therefore needs both a storage count and a measure
of what the reconstructed model does.

Weight quantization makes this approximation explicit. We will store each
weight as a signed four-bit code, keep a positive scale for a small group of
weights, and multiply the code by that scale when loading the model. The
existing `f64` matrix multiplication and model remain our execution path.

Start with this constructed matrix and input row:

$$
W=\begin{pmatrix}-7&-3.5&0&3.5\\0.1&0.2&0.3&7\end{pmatrix},\qquad
x=\begin{pmatrix}1&2\end{pmatrix}.
$$

$W$ has shape $[2,4]$, $x$ has shape $[1,2]$, and the product $y=xW$ has
shape $[1,4]$. These values are an explanatory fixture, separate from the
learned model we will compare later.

### Let one scale cover each row

A group size $g=4$ places each complete row in one group. The largest absolute
weight in either row is $7$. Choosing scale $s=7/7=1$ makes code $7$ represent
weight $7$ and code $-7$ represent weight $-7$.

Divide each weight by its scale and round to the nearest integer. Our tie rule
rounds halfway values away from zero: $-3.5$ becomes $-4$, and $3.5$ becomes
$4$. In the second row, $0.1$, $0.2$ and $0.3$ all round to zero because the
scale is still $1$. The resulting signed codes and reconstructed matrix are

$$
Q_4=\begin{pmatrix}-7&-4&0&4\\0&0&0&7\end{pmatrix},\qquad
\widehat W_4=\begin{pmatrix}-7&-4&0&4\\0&0&0&7\end{pmatrix}.
$$

The equal code and weight values here follow from scales of $1$; codes do not
generally have the same numerical value as reconstructed weights. In
particular, sharing a scale with the large weight $7$ erased the three small
values in the second row.

### Give smaller groups their own scales

For $g=2$, split each row into its first two and last two entries. The four
scales, in row order, are ideally

$$
\left(1,\;0.5,\;\frac{0.2}{7},\;1\right).
$$

The first row's last group now represents $3.5$ exactly as code $7$ times
scale $0.5$. The second row's first group no longer shares a scale with $7$:
$0.1/(0.2/7)=3.5$ rounds to code $4$, while $0.2$ uses code $7$. Its last
group still contains $0.3$ and $7$, so $0.3$ still becomes zero. The codes are

$$
Q_2=\begin{pmatrix}-7&-4&0&7\\4&7&0&7\end{pmatrix}.
$$

The actual Rust report prints the third scale as `0.028571428571428574` and
the reconstruction of the source value `0.1` as `0.1142857142857143`.
These are stored `f64` observations. The ideal expression $4(0.2/7)$ explains
the intended reconstruction; its decimal appearance does not make all the
intermediate operations exact in binary floating point.

## Fit, round and reconstruct within each row group

For a nonempty matrix with $R$ rows and $C$ columns, choose a positive integer
group size $g$. Partition every row into contiguous groups of at most $g$
weights. A final shorter group keeps its own scale; groups never cross rows.
For the index set $H$ of one such group, use

$$
\begin{aligned}a&=\max_{i\in H}|w_i|,&s&=\begin{cases}a/7,&a>0,\\1,&a=0,\end{cases}\\q_i&=\operatorname{clamp}(\operatorname{round}_{\mathrm{away}}(w_i/s),-7,7),&\widehat w_i&=s q_i.\end{aligned}
$$

$w_i$ is source weight $i$ in the group; $a$ is the group's largest absolute
weight. The scale $s$ gives the weight change represented by one integer code
step. Dividing by $s$ converts a weight to code units; rounding selects the
nearest level, and clamping restricts the result to $-7$ through $7$.
$q_i$ is the dimensionless signed code, and $\widehat w_i$ is its reconstructed
weight in the original weight units. The subscript “away” specifies that a
halfway value moves away from zero.

This is a symmetric representation with zero point $0$: code $0$ reconstructs
weight $0$. It uses $15$ levels, from $-7$ through $7$. Four signed bits could
also encode $-8$, but this course representation reserves and rejects that
code. An all-zero group uses $s=1$: the positive fallback keeps division
defined and gives only zero codes and zero reconstructions. It does not
preserve the sign of a floating-point zero.

### Separate rounding error from clipping error

In ideal real arithmetic, suppose $s>0$ and the ratio $w_i/s$ lies within
$[-7,7]$, so clamping does not change the rounded result. Nearest-integer
rounding then gives

$$
\left|q_i-\frac{w_i}{s}\right|\le\frac12
\quad\Longrightarrow\quad
|\widehat w_i-w_i|\le\frac{s}{2}.
$$

Multiplication by the positive scale converts a half-code-step distance to
a half-scale weight error. The away-from-zero tie rule attains that bound at
either halfway value. Fitting the scale from the absolute maximum keeps the
ideal source ratios inside the code range.

A supplied fixed scale is a different situation. At scale $1$, halfway
values $0.5$ and $-0.5$ become codes $1$ and $-1$. With $s=1$, source weight
$10$ rounds beyond the range and clips to code $7$; reconstruction is $7$ and
absolute error is $3$. Source weight $-10$ similarly becomes $-7$. The
half-scale bound does not apply to these clipped values. The scalar Rust
helper supports this explicit fixed-scale contrast; it is separate from
fitting an absolute-maximum scale to the group.

The implementation also rounds during `f64` scale fitting, division and
reconstruction. The ideal inequality is therefore not a universal exact
`f64` guarantee. Nonfinite weights, nonpositive or nonfinite scales, and
nonfinite reconstructions are refused. Even a positive finite absolute
maximum can be too small: dividing it by $7$ can underflow to zero, which is
an invalid scale.

### Pack two signed codes into one byte

Keep the codes in row-major order. Encode each signed code as a four-bit
two's-complement nibble, put the first code in the low four bits of a byte,
and put the next code in the high four bits. For example, code $-7$ has
nibble `9`, and code $-4$ has nibble `C`. Their byte is `C9`: the low nibble
still belongs to the first weight.

The $g=4$ code stream `[-7,-4,0,4,0,0,0,7]` packs as `C9 40 00 70`.
For $g=2$, `[-7,-4,0,7,4,7,0,7]` packs as `C9 70 74 70`. These hexadecimal
bytes are storage literals, not floating-point values. Nibble `8` would
decode as the reserved code $-8$ and is rejected.

Packing follows the continuous code stream, so one byte may contain the last
code of one row and the first code of the next. Scale lookup still uses each
code's row and column. An odd total code count leaves the final high nibble
unused and zero. For the one-row fixture `[-7,-3.5,0,3.5,7]` with $g=4$,
the last weight forms a shorter second group; scales are $[1,1]$ and packed
bytes are `C9 40 07`. The high half of `07` is padding, not another weight.

Mean squared error is $\mathrm{MSE}=M^{-1}\sum_{k=1}^{M}(\widehat z_k-z_k)^2$:
$z_k$ and $\widehat z_k$ are the source and reconstructed values being compared,
and $M$ counts those values. Here $M=8$ for weights and $M=4$ for product
outputs. MSE uses squared weight or output units; maximum absolute error
uses the corresponding original units. Error summaries are rounded to twelve
decimal places after calculation, while the report retains the normal `f64`
printing of scales and individual reconstructed values.

The connection to a product is explicit in ideal arithmetic. Let
$E=\widehat W-W$ be the matrix of weight errors. Then

$$
\widehat y-y=xE,\qquad
|\widehat y_j-y_j|\le\sum_{i=1}^{2}|x_i|\,|E_{ij}|.
$$

Output index $j$ selects one column; input coordinate $i$ weights the error
in row $i$ of that column. The triangle inequality gives the bound by adding
those absolute contributions. This local linear result explains why weight
error can change a layer's output. It does not bound the quality of an entire
transformer. Smaller groups improve the MSE in this fixture, but do not prove
that every value or language-model score improves for every group size.

### Count scales and complete files as well as codes

For one matrix, the number of weights is $N=RC$, and the number of row groups
is $G=R\lceil C/g\rceil$. The original `f64` weight payload uses $8N$ bytes.
Packed codes use $\lceil N/2\rceil$ bytes, and the `f64` scales add $8G$ bytes.
The tiny matrix therefore uses $4+32=36$ code-and-scale bytes for $g=2$, or
$4+16=20$ for $g=4$, compared with $64$ original weight bytes. These subtotals
omit logical shape, other tensors, configuration and the file header.

Each independently stored matrix has its own final padding nibble. For many
matrices, add their individual code-byte counts
$\sum_t\lceil N_t/2\rceil$, where $N_t$ is the weight count of matrix $t$;
rounding the combined weight count once could miss padding between matrices.

training job for $2$ updates, snapshots that state once, and derives both
group sizes from it. There are $22$ learned matrices containing $1544$
weights. Gains, model constants and text assets retain their original payloads.

<div id="weight-quantization-history" data-review-id="weight-quantization-history">

## Relate integer representation to inference arithmetic

A shared scale makes the largest magnitude determine the spacing available to smaller values; representation alone also leaves execution costs unresolved.

Jacob and colleagues describe a scaled affine integer representation and the additional arithmetic needed for integer-only inference. The linked author preprint dates from 2017; the work appeared at CVPR 2018.
In that [author preprint](https://arxiv.org/pdf/1712.05877), the affine
representation is $r=S(q-Z)$, where $r$ is the represented real value, $q$ is
an integer, $S>0$ is a scale and $Z$ is the code corresponding to real zero.

Dettmers and colleagues discuss absolute-maximum quantization and combine vector-wise scaling with mixed-precision treatment of transformer outlier features.
Their [LLM.int8() paper appeared at NeurIPS 2022](https://papers.nips.cc/paper_files/paper/2022/file/c3ba4962c05c49636d4c6206a97e9c8a-Paper-Conference.pdf).
LLM.int8() combines vector-wise scaling with a separate higher-precision path for transformer outlier features.
This does not make our tiny matrix an outlier study of a large transformer.

Measure both numerical changes and model scores when reducing stored precision, and distinguish the stored representation from the arithmetic used for inference.
Our reference contrast is narrower: keep the original `f64` matrix product,
then run it again with weights reconstructed from codes and scales.

The row groups, four-bit range, reserved code and tie policy here are course
choices. This implementation reproduces neither paper, GPTQ nor AWQ, and
makes no claim to their quality or speed results. The Rust contrast below
isolates lossy weight storage from execution engineering.

</div>

`PortableModel::quantize_weights` derives an archive from all and only the
rank-two learned matrices. Other learned gains, model constants and text
assets keep their original records. The existing native `config-lib`
settings name the versioned scheme and group size; SafeTensors owns the
container format. The method refuses an already quantized source rather than
silently quantizing its reconstruction again.

Restoration checks the descriptor and typed records, reconstructs logical
matrices, and passes them through the existing decoder or backbone
constructors. The text embedding and output head still share one live table;
a generic backbone archive needs no tokenizer. This is lossy inference
storage. Exact training resume retains Chapter 15's unquantized
model/optimizer/random-state compatibility envelope and rejects packed model
state, even inside an otherwise checksum-valid training checkpoint.

## Reproduce the report and load the saved packed model

From the repository root, with Docker and the existing course Docker setup
available, run the default CPU example. The matrix, native configuration and
small training job are included; no external corpus or downloaded model is
needed.

```bash
COURSE_CORPUS=false ./course run cargo run --quiet --offline --locked -p practical-ch17-weight-quantization
```

The JSON contains `matrix_probes`, `source`, `quantized_models`,
`reference_updates: 2` and `source_unchanged: true`. It reports both group
sizes, their packed bytes, errors, storage and fixed-document scores. The
default serialized-model comparisons reload bytes in the same program.

To use actual saved files across separate programs, keep the same
repository-root working directory and Docker setup and run this entire block
as one command. One Docker session retains the files while each Rust program
exits before the next program starts.

```bash
COURSE_CORPUS=false ./course run sh -c '
set -eu
mkdir -p tmp/ch17-quantization-flow
cargo run --quiet --offline --locked -p practical-ch15-save-load-resume-model -- train --until 2 --model tmp/ch17-quantization-flow/parent.safetensors --checkpoint tmp/ch17-quantization-flow/parent.train
cargo run --quiet --offline --locked -p practical-ch17-weight-quantization -- quantize --model tmp/ch17-quantization-flow/parent.safetensors --output tmp/ch17-quantization-flow/group4.safetensors --group-size 4
cargo run --quiet --offline --locked -p practical-ch15-save-load-resume-model -- infer --model tmp/ch17-quantization-flow/group4.safetensors --prompt ab --tokens 3
cargo run --quiet --offline --locked -p practical-ch16-language-model-evaluation -- evaluate --model tmp/ch17-quantization-flow/group4.safetensors --batch-rows 1
'
```

The first program saves the source model after $2$ updates and its separate
training checkpoint. The second saves the $g=4$ inference archive; the
unchanged Chapter 15 inference and Chapter 16 evaluation commands then load
that archive without training. The quantizer's `model_id`, inference's
`model_id` and evaluator's `model_sha256` all identify the derived model as
`ba40116d31d1d7c25b63fc8b6dca03d0e4a510d3efdc3a29a50ec058948fa12f`.

Inference reports `device: "cpu"`, `precision: "f64"` and `tied_alias: true`.
Its generated IDs are `[108,27,159]`; the corresponding bytes `[106,25,157]`
do not form useful prose.
Evaluation prints validation NLL $5.460701$ and perplexity $235.262392$,
with $9$ selected targets, $2$ batches and zero recorded graphs. Equal printed
metrics establish agreement at the stated six-decimal display precision.
This bounded CPU run does not establish GPU performance or useful language
generation. Separate `./course run` invocations would use disposable
containers and lose the saved files between programs.

  <li id="weight-quantization-answer-1">For $g=4$, the first row's scale is $1$ and $3.5$ rounds away from zero to code $4$, reconstructing $4$. For $g=2$, its group contains $0$ and $3.5$, so the scale is $0.5$ and code $7$ reconstructs $3.5$. At fixed scale $1$, source weight $10$ saturates at code $7$ and has absolute error $3$. That clipped example is outside the ideal no-clipping half-scale bound.</li>
  <li id="weight-quantization-answer-2">The low nibble <code>9</code> represents code $-7$; the high nibble <code>C</code> represents $-4$. The five source weights form groups of four and one, with scales $1$ and $1$. The first four codes occupy <code>C9 40</code>; the last code $7$ occupies the low nibble of <code>07</code>. Its high zero nibble is unused padding. A shorter row group still represents a real weight and has a scale; padding represents no weight.</li>
  <li id="weight-quantization-answer-3">Both weight maxima are $0.5$, but the errors occur in different entries. The identity $\widehat y-y=xE$ explains the different weighted column sums; equal maximum weight error does not imply equal product error.</li>

## Keep the model path while changing its saved representation

The learned matrices now have an explicit code-and-scale storage option. The
same text encoder, source-independent backbone and tied head load their
reconstructed weights and use the existing CPU evaluator and generator. The
comparison keeps smaller saved storage distinct from numerical error, model
likelihood, live memory and execution speed. Exact training continuation
still needs the original unquantized training state.

Planned Chapter 18, Grouped-query attention and context masks, will extend
attention sharing and the context permitted in full and cached computation.
That changes a different part of the model than the weight representation
studied here.
