## Extend a complete model to larger workloads

A working small language model makes every operation visible. Larger workloads
put pressure on several connected parts at once: more text increases
tokenization and batching work; deeper models carry more weights and intermediate
activations; learning retains gradients and optimizer state. Reducing numerical
precision can shrink that storage while changing rounding and overflow behavior.
Generation repeatedly reads an expanding prefix. A change that saves storage can
also change which tokens contribute to loss or which earlier positions attention
can read. The practical task is to improve how the model runs while keeping those
mathematical choices explicit.

*Practical LLM in Rust* starts from the completed model in *LLM from scratch*.
Its separate implementation lives in `rust/crates/llm-from-scratch-practical`.
We extend its tokenizer, tensors, automatic differentiation, causal decoder,
training, evaluation, checkpoints and cached generation as one continuing
system. Chapter 0 locates those parts and the course chapters; Chapter 1 begins
the experiments.

## Bring the first course's model with you

Complete [LLM from scratch through Chapter 39](../../course/39-end-to-end-llm/)
or bring equivalent experience with Rust, byte-pair encoding, tensors, gradients,
causal attention and next-token training. The [first course](../../course/)
derives and implements those mechanisms. This course uses that foundation to
explain changes in data layout, numerical execution, training and inference.

The default CPU build and CPU inference work without NVIDIA hardware. Published
<a href={chapterHref(11)}>Chapter 11</a> adds explicit CPU or CUDA selection for
matrix products and sum/mean reductions in the shared forward and backward
paths. Selecting CUDA requires compatible NVIDIA hardware and runtime libraries;
an unavailable CUDA request is refused. This boundary does not make every
operation GPU-resident, and other GPU backends are not implemented.

The external corpus-preparation example separately uses NVIDIA NeMo Curator and
needs a device and driver compatible with its pinned CUDA/RAPIDS environment.
NeMo prepares text outside the Rust model. Another preparation tool can supply
the same document format, and Rust can load already prepared documents on CPU.

## Continue from the completed small model

The first course builds the mechanisms and assembles a complete causal language
model. The practical course begins at that completed system and changes how its
parts handle larger workloads. The first course keeps its own implementation;
the practical copy evolves independently. Each extension should therefore have
a clear connection to the model already present and a concrete reference for
comparison.

## Follow one model through learning and generation

Prepared documents become token IDs and document-aware examples. Batching keeps
each example's permitted context and real next-token targets intact. The text
encoder uses embedding lookup to turn input IDs into vectors, accompanied by
position and attention information. The causal transformer turns those vectors
into hidden features. The text head uses the same learned embedding table to
map the features to vocabulary scores, called logits.

Learning and generation use those scores differently. Learning compares scores
with observed next-token targets to calculate loss. Gradients describe how
changes in weights affect that loss, and the optimizer changes the same weights
used by the next forward calculation. Generation chooses another token according
to a decoding policy, returns its ID to the text encoder and runs a subsequent
decoder step. Compatible cached attention keys and values let that step reuse
earlier prefix work.

state that later inference can use. Neither is another token-processing stage
between the encoder and the text head.

<a href={chapterHref(10)}>Chapter 10</a> already implements the text
encoder, source-independent transformer backbone and tied text head. The
backbone consumes vectors and their layout without requiring a tokenizer or
vocabulary. Observed targets enter the learning branch outside that backbone.
Text remains the only worked input and output modality. A compatible
encoder for images, binary data or entities would still need suitable encoding
and training; the shared vector boundary alone does not give the text model
those capabilities.

## Preserve learned weights for later use

The starting model already has checkpoint mechanisms. Published
<a href={chapterHref(15)}>Chapter 15</a> extends that work to saving and loading
the encoder, backbone and head composition. It saves named weights, semantic
settings and the tokenizer assets needed by the complete text model, stores the
tied table once and restores its shared identity. The model can be saved,
its process can exit, and a fresh local CPU process can load it for inference.
The generic backbone remains independent of a text tokenizer.

Portable saved weights do not contain mandatory device addresses or CUDA handles.
The fuller training checkpoint additionally preserves optimizer, update-policy,
random-generator, data-position, loss-scaler and accumulation state. Exact
continuation is checked at complete-update boundaries with cleared gradients,
matching data and the same-binary scalar CPU `f64` execution envelope. These
training conditions are narrower than the requirements for CPU inference.

The separate physical portability experiment performs a CUDA training update,
saves the model, exits and loads the same learned weights on CPU without
retraining. That experiment remains pending; the implemented CPU save/load and
continuation fixtures do not establish it.

## Keep the experiments at their stated scale

Small fixtures expose values that are easy to inspect: token boundaries, allowed
attention positions, a loss, a gradient or a restored state. They establish the
behavior shown for those inputs. A CPU fixture cannot establish a physical-GPU
result; a bounded CUDA primitive comparison cannot establish whole-model training
throughput. Neither by itself establishes full-corpus throughput, broad language
quality or a larger model's memory use. Full-data preparation and larger hardware
experiments need their own measurements.

The course focuses on LLM mathematics, numerical choices, training and inference.
A thin local command-line interface is intended to make experiments with this
same model convenient. Application-specific web services, retrieval and tool
frameworks are outside the roadmap.

## Begin with the fixed reference experiment

The data path supplies the model's inputs; learning changes its weights;
generation uses those weights to extend a sequence. Later lessons extend these
connected roles and compare the result with a declared reference. Start with
<a href={chapterHref(1)}>Chapter 1: Keep a fixed reference before extending the decoder</a>
to establish the small experiment and the limits of what it demonstrates.
