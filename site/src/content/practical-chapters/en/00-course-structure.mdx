## Start from a working model

This course starts from a working language model and studies what must change as
the data, model and workload grow. The starting implementation is a separate
copy of the model completed in *LLM from scratch*. It already contains byte-pair
tokenization, tensors, automatic differentiation, a causal decoder, training,
evaluation, checkpoints and cached generation. Here we extend those parts.

Chapter 0 is an orientation. Chapter 1 begins the learning material by recording
exactly what the small reference model demonstrates. That record gives later
changes a concrete comparison point.

## Before starting

Complete [LLM from scratch](../../course/) or bring equivalent experience with
Rust, byte-pair encoding, causal attention, gradients and next-token training.
The first course's [Chapter 39](../../course/39-end-to-end-llm/) shows the complete
small model. Familiarity with that model matters more than memorizing its
chapter numbers.

The initial reference and Rust loading of an already prepared corpus run on a
CPU. The planned accelerated training path will use CUDA and require a compatible
NVIDIA GPU. CPU inference remains part of the planned path.

The external corpus-preparation example separately uses NVIDIA NeMo Curator. It
needs a GPU and driver compatible with its pinned CUDA/RAPIDS environment. NeMo
prepares text outside the Rust model; another tool can supply the same
prepared-document format.

## Keep the completed model as the starting point

The first course builds the mechanisms of a small causal language model. This
course begins with its completed implementation and studies how data handling,
execution, training and inference must change for larger workloads. The Rust
implementation for this course lives in
`rust/crates/llm-from-scratch-practical`. Its examples extend that copy; the first
course keeps its own implementation.

## Follow the practical path

1. [Chapter 1: Record the reference model](../01-reference-core-handoff/) binds
   the tiny experiment to its inputs and separates repeatable results from
   claims about language quality or speed.
2. [Chapter 2: Prepare a corpus](../02-corpus-preparation/) separates external
   text preparation from Rust loading, and preserves document and split identity.
3. [Chapter 3](../03-scalable-bpe-tokenizer/) extends byte-pair encoding. It adds
   bounded ingestion, local pair updates and efficient application of frozen
   merge ranks to the existing tokenizer.

The [practical course index](../) links to the lessons currently available.
Published Chapters 4–9 continue with variable-length batches and packing,
configurable decoder depth and shape, optional dropout and explicit failure
boundaries.

The planned continuation extends that same causal text model through 23 future
lessons, Chapters 10–32. These chapters describe planned work, not completed
implementations or measurements.

| Chapter(s) | Learning focus |
| --- | --- |
| 10–15 | Chapter 10, “Separate input encoding from the transformer”, will implement the existing text model's input boundary. Chapter 11 will add GPU tensor execution, followed by mixed precision, gradient accumulation and activation recomputation, then optimizer schedules and clipping. Chapter 15 will add saving and loading of the composed model for local use, then training resume. |
| 16–22 | Evaluate loss and overfitting, quantize weights, extend attention and its key/value cache, transform sampling distributions, and generate in batches. |
| 23–27 | Supervised fine-tuning (SFT) on response tokens; low-rank adaptation (LoRA), including over quantized weights; direct preference optimization (DPO) from chosen/rejected responses. Then reuse prefix caches and study rotary position embeddings (RoPE) with context scaling. |
| 28 | A local capstone combines training or adaptation, saving, resuming, evaluation, quantization and generation with the same model. |
| 29–32 | Beam search, speculative proposal verification, distributed-training mathematics through local sharding and collective examples, and a tiny mixture-of-experts (MoE) model built from existing feed-forward blocks. |

Chapter 10 will route the existing model's forward calculation, training and
cached generation through the input boundary. Its text encoder will reuse
tokenization and embedding lookup to prepare a checked sequence of embedding
vectors with position and attention information. The shared transformer will
accept that sequence without requiring text tokens or a tokenizer and return
hidden features. The text output head will reuse the existing tied projection
to map those features to token logits.

Separating these responsibilities will let other compatible source encoders
supply vectors without changing the shared transformer. The course will
implement only this text encoder and text output head. Other sources will still
need suitable encoding and training.

Chapter 15 will save the composition, weights and settings of the text encoder,
shared transformer and text output head, keeping tied weights shared and
including the tokenizer assets needed to restore this text model. It will then
load the model in a fresh local process for generation. The saved model is
intended to be independent of the training GPU:
the portability check will be to train or update with CUDA, save, exit, and load
the same weights on CPU without retraining. CUDA training is not intended to
make inference NVIDIA-only. Exact training resume will add optimizer,
random-generator, data-position and accumulation state and may require a more
specific execution environment.

A shared local command-line interface is planned for experimenting with this
same model: training, saving and loading, evaluating, and generating text.
Application integration is outside this roadmap.

## Read the examples at their stated scale

Small fixtures make intermediate values inspectable: a pair count, a token
sequence, a loss or a restored state. They establish the behavior shown for
those inputs. They do not establish full-corpus throughput, useful generated
language, or a larger model's memory use. Full-data runs and hardware
measurements supply that separate evidence.

## Continue with the reference experiment

Corpus preparation and tokenization supply the causal decoder's inputs. Later
chapters change how that same model is configured, trained, evaluated and used
for generation. Start by establishing the reference experiment in
[Chapter 1](../01-reference-core-handoff/).
