## Separate a better training fit from better held-out scores

An optimizer receives the training targets and changes weights to reduce their
loss. That feedback can improve the fit to those particular documents while
making separate documents less likely. A falling training loss therefore leaves
an important part of the result unmeasured. We need to freeze the same learned
weights, score both training and held-out targets without updating them, and
keep the scoring rules comparable.

Use [Chapter 4's valid-target masks](../04-padded-variable-batches/),
[Chapter 5's document-local packed contexts](../05-packed-sequence-masks/),
[Chapter 8's training and evaluation modes](../08-dropout-semantics/),
[Chapter 13's accumulated updates](../13-gradient-accumulation-recomputation/)
and [Chapter 15's portable model](../15-save-load-resume-model/) as prerequisites.
We extend their existing model, loss, trainer and saved-state paths.

### Follow one measured run

Fix two training documents, `aaab` and `aab`, and two validation documents,
`abaa` and `baa`. Only the training documents enter optimizer updates. For
initialization seed $39$, the measured training mean negative log-likelihood
(NLL) falls from $0.874321$ nats per target after update $20$ to $0.157051$
after update $80$. Over the same interval, validation NLL rises from $1.267297$
to $4.172745$. Lower training loss has accompanied worse validation likelihood.

The rise is visible in each of the two observed intervals, $20\to40$ and
$40\to80$, for all three predeclared seeds $39$, $40$ and $41$. This is the
experiment's bounded **overfitting** signal. A training/validation gap alone
would not establish that change over time. Different string order and difficulty
can also affect a gap between the splits.

### Keep the target occurrences explicit

The existing Chapter 4 tokenizer is fixed before these examples are encoded;
validation is not used to fit it. Its document encoding includes beginning-of-
sequence (BOS) ID `0`, content IDs `99` for `a` and `100` for `b`, and
end-of-sequence (EOS) ID `1`.

## Add token losses before taking a mean

A short batch must not receive the same total weight as a longer batch merely
because both produce one mean. To expose the denominator, use two constructed
lists of assigned target probabilities: $[0.5,0.25]$ and
$[0.5,0.5,0.25,0.5]$. These probabilities are a separate arithmetic probe,
not outputs from the trained decoder.

The lists have $2$ and $4$ targets and total NLLs $3\ln2$ and $5\ln2$ nats.
Together they contain $6$ targets and $8\ln2$ nats. The correct mean is
$\frac{4}{3}\ln2\approx0.924196$ nats per target; its perplexity is
$2^{4/3}\approx2.519842$. Averaging the two batch means instead gives
$\frac{11}{8}\ln2\approx0.953077$, which overweights each target in the short
batch. Averaging the two perplexities gives $2.603421$ and is also the wrong
aggregation for these six targets.

For one fixed model and one evaluated split, the general rule is

$$
\begin{aligned}
S_b&=-\sum_{i\in I_b}\ln p_\theta(y_i\mid x_i),&N_b&=|I_b|,\\
S&=\sum_b S_b,&N&=\sum_b N_b>0,\\
L&=S/N,&\mathrm{PPL}&=\exp(L).
\end{aligned}
$$

Batch index $b$ selects a batch, and $I_b$ contains its valid target occurrences.
Index $i$ names one occurrence, $y_i$ is its observed next token, and $x_i$ is
the permitted document-local context. The fixed learned parameters are $\theta$;
$p_\theta(y_i\mid x_i)$ is the probability assigned by the unmodified evaluation
distribution, without sampling filters or temperature changes.

The natural logarithm $\ln$ makes $S_b$ and total $S$ losses in nats. Counts
$N_b$ and total $N$ count selected targets, including selected EOS targets and
excluding padding. Mean $L$ is in nats per target; $\mathrm{PPL}$ is dimensionless.
Sum the numerators and denominators before dividing, then exponentiate once.
For a comparison to be interpretable, keep vocabulary, selected targets,
document-context policy and numerical execution explicit and comparable.

## Read the measurements at their stated scale

The model has residual width $8$, two attention heads, feed-forward width $16$,
one decoder block and capacity for $8$ positions. Each seed performs $80$
scalar CPU `f64` logical updates at constant rate $0.02$, combining two
one-document microbatches per update. AdamW uses $\beta_1=0.9$,
$\beta_2=0.999$, $\epsilon=10^{-8}$ and zero weight decay. Global gradient
clipping uses limit $1$; dropout is disabled in this training fixture.
Data, tokenizer, update policy and evaluated checkpoints are fixed across seeds.

All five checkpoints, $0,10,20,40,80$, appear for every seed in the figure below.
Update $20$ has the smallest validation NLL among those five observations in
each run. That does not make it the optimum among all possible update counts:
intermediate updates were not evaluated. No early-stopping or best-seed selection
algorithm is introduced. The saved example deliberately uses the first
predeclared seed, $39$, at final update $80$.

The final validation NLLs for seeds $39$, $40$ and $41$ are $4.172745$,
$4.328176$ and $2.545169$ nats per target. Their arithmetic mean is $3.682030$,
sample standard deviation is $0.987613$, and observed range is
$2.545169$–$4.328176$ nats per target. For $K=3$ seeds, with $L_k$ denoting
seed $k$'s final validation NLL and $\bar L$ their arithmetic mean, the sample
standard deviation is $s=\sqrt{\sum_{k=1}^{K}(L_k-\bar L)^2/(K-1)}$.
Here $k$ indexes runs rather than token occurrences, and $s$ has the same units
as $L_k$.

These numbers describe initialization variation conditional on this one split
and training policy. They are not a population confidence interval or a measure
of uncertainty from sampling different documents. Three fixed seeds also do
not establish that a model ranking would persist on other data or seeds.

The arithmetic uses represented `f64` values. The report rounds metric values
to six decimal places after calculation; comparison and seed statistics use
unrounded values. A finite NLL need not have a finite represented exponential
for every possible input, although the reported perplexities here are finite.

## Compare likelihood without making it a complete quality judgment

Short-context count models provide a useful comparison, but fitting the observed
training transitions does not establish performance on separate documents.
Neural language models learn distributed representations and can be compared
with n-gram models through held-out likelihood and perplexity.

In [*A Neural Probabilistic Language Model*](https://jmlr.org/papers/volume3/bengio03a/bengio03a.pdf)
(2003), Bengio, Ducharme, Vincent and Jauvin compare neural and n-gram language
models with perplexity derived from average negative log-likelihood, separating
training, validation choices and final testing. Distributed representations address limitations of short
count-based contexts. This chapter retains the comparison principle, using
the existing bigram as a deliberately simple reference.

Fit the existing add-one-smoothed bigram only to the two training documents and
their $9$ adjacent transitions. For previous token $u$ and next token $v$, it
uses $q(v\mid u)=(C_{uv}+1)/(C_u+V)$, where $C_{uv}$ counts that training
transition, $C_u$ counts all training transitions leaving $u$, and $V$ is the
same tokenizer vocabulary size used by the decoder. The added count prevents
an unseen transition from receiving zero probability. The bigram uses only the
previous token; the neural decoder can use the permitted longer prefix.

Both models score the same $9$ selected target occurrences on each split.
The frozen bigram has training NLL $4.402665$ and perplexity $81.668227$;
validation NLL is $5.044970$ and perplexity $155.239620$. The neural seed-$39$
model at update $80$ has lower validation NLL, $4.172745$, and perplexity
$64.893323$. It beats this weak baseline while scoring worse than its own
update-$20$ validation result, NLL $1.267297$ and perplexity $3.551242$.
Beating a baseline does not erase deterioration during continued training.

In [*Language Model Evaluation Beyond Perplexity*](https://aclanthology.org/2021.acl-long.414.pdf)
(2021), Meister and Cotterell explain that held-out perplexity is a monotonic
transformation of average token log-likelihood and does not identify in detail
which linguistic properties a model learned. The decoder's evaluation must
preserve target accounting and split separation, while aggregate likelihood
remains narrower than a detailed account of learned linguistic properties.
These constructed strings establish neither useful generated language
nor broad language capabilities.

Fit the existing add-one-smoothed bigram only to training documents, then compare
its probabilities with the neural decoder on the same selected targets. The
bounded Rust comparison measures both models on four constructed strings. Its
tokenizer, baseline, seeds and update budget are course choices, not a
reproduction of either paper's results or a competitive n-gram benchmark.

</div>

## Reproduce the scores and inspect the saved model

From the repository root, with Docker and the existing course Docker setup
available, run the default CPU example. No GPU, external corpus or downloaded
model is required; the four documents and fixed experiment settings are included.

```bash
COURSE_CORPUS=false ./course run cargo run --quiet --offline --locked -p practical-ch16-language-model-evaluation
```

The JSON contains `weighting`, `layout_comparison`, `baseline`, all three
`runs`, `final_validation_seed_summary` and `saved_first_seed_model`.
Each run contains the five checkpoints and its two observed overfitting
intervals. The default saved-model comparison is an in-memory round trip.

For a real process boundary, keep the same working directory and Docker setup
and run this entire block as one command. Each Cargo invocation exits before
the next program starts; one container retains their saved file.

```bash
COURSE_CORPUS=false ./course run bash -euc '
mkdir -p tmp/ch16-evaluation
cargo run --quiet --offline --locked -p practical-ch16-language-model-evaluation -- experiment --save-model tmp/ch16-evaluation/model.safetensors
cargo run --quiet --offline --locked -p practical-ch16-language-model-evaluation -- evaluate --model tmp/ch16-evaluation/model.safetensors --batch-rows 1
cargo run --quiet --offline --locked -p practical-ch16-language-model-evaluation -- evaluate --model tmp/ch16-evaluation/model.safetensors --batch-rows 2
'
```

The producer saves seed $39$ at update $80$, not the seed with the smallest
validation score. Both new evaluation programs restore model identity
`f485cea6228baa825076855af99cc71bad66b462c540590a4767df9064e07e2d`.
Their printed training NLL is $0.157051$ and validation NLL is $4.172745$;
each split has $9$ targets and zero recorded graphs. One row per batch produces
two batches per split; two rows produce one. The printed metrics match at six
decimal places. That printed equality alone does not establish the unrounded
$10^{-12}$ tolerance checked by the Rust layout tests. Separate `./course run`
invocations would use disposable containers and would not retain this file.

With the same repository-root working directory and Docker setup, run the demo
library tests:

```bash
COURSE_CORPUS=false ./course run cargo test --offline --locked -p practical-ch16-language-model-evaluation
```

The library result is ten passed tests. They cover target weighting, layout
agreement, preserved nonzero gradients and explicit evaluation dropout,
split/binding refusals, the training-only baseline and the saved composition.
