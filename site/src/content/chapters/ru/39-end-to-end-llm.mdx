## Сначала предскажите границы доступа, затем результат

В корпусе есть $8$ документов обучающей выборки, $2$ документа валидационной
выборки и $2$ документа тестовой выборки. Первый вопрос относится к потоку
информации. Только обучающие документы могут определять порядок BPE-слияний,
участвовать в обновлении параметров декодера и обучать частотную базовую модель.
По валидационной выборке можно выбрать уже обученное состояние. Тестовые данные
не могут делать ни того, ни другого.

Восемь BPE-слияний, обученных только по обучающей выборке, дают словарь размера
$266$. При длине контекста $C=4$ закодированные выборки образуют $1820$, $463$ и
$436$ каузальных окон. Для обновлений используются мини-пакеты по $16$ окон.
При трёх проходах оценки мини-пакет содержит не более $128$ окон, поэтому по
обучающей, валидационной и тестовой выборкам получается соответственно $15$,
$4$ и $4$ мини-пакета. Декодер состоит из одного блока с одной головой; ширина
модели и ширина слоя прямого распространения равны $4$. Всего в нём $1188$
обучаемых скалярных параметров.

Перед тем как читать результат, предскажите:

1. выберут ли два запуска обучения с зерном $39$ одно и то же состояние с
   побитовым совпадением;
2. станет ли значение функции потерь на тестовой выборке доступно до фиксации
   этого состояния;
3. изменится ли после восстановления из контрольной точки хотя бы один логит
   для отдельной пробы <code>At</code>;
4. изменит ли генерация с кэшем хотя бы одно решение при сэмплировании.

Оба запуска обучения выбирают шаг $32$ со значением функции потерь на валидации
$3.889531885$. Только после выбора программа формирует мини-пакеты тестовой
выборки и передаёт их одному локальному объекту итоговой оценки. Каждое из $436$
тестовых окон содержит $C=4$ целевые позиции:

$$
N_{\mathrm{test}}=W_{\mathrm{test}}C=436\cdot4=1744.
$$

Декодер и зафиксированная биграммная модель со сглаживанием $\alpha=1$ оценивают
одни и те же $1744$ целевые позиции. Значение функции потерь декодера равно
$3.866087547$, а биграммной модели — $3.981342714$. В этом запуске преимущество
декодера составляет $0.115255167$.

Контрольная точка размером $30994$ байта после повторного кодирования даёт те же
байты и точно восстанавливает модель, оптимизатор, токенизатор и состояние
генератора псевдослучайных чисел. Отдельная проба <code>At</code> кодируется как
<code>[67,118]</code> и воспроизводит каждый бит логитов. Затем генерация
начинается с промпта <code>A</code>, закодированного точным числовым ID токена
<code>67</code>. При $\tau=0.8$, $k=4$ и зерне $38$ выбираются числовые ID
<code>[260,34,34]</code>, которые декодируются как <code>т␠␠</code>. Каждый
знак <code>␠</code> обозначает один сгенерированный пробел. Пути с KV-кэшем и с
расчётом по полному префиксу используют одинаковые случайные числа и принимают
одинаковые решения.

## Одно произведение связывает все решения о следующем токене

Полная модель по-прежнему отвечает на вопрос, поставленный в начале курса:

$$
P_\theta(z_{1:T})=\prod_{t=1}^{T}P_\theta(z_t\mid z_{<t})
$$

Вероятность последовательности $P_\theta(z_{1:T})$ равна произведению условных
вероятностей. При обучении минимизируется отрицательный логарифм этих условных
вероятностей; по валидационной выборке выбирается $\theta$; итоговая оценка
измеряет уже выбранное $\theta$; при генерации новый $z_t$ выбирается из
условного распределения при известном $z_{<t}$.

Эта факторизация задаёт каузальное ограничение. Вероятность в позиции $t$ может
зависеть от $z_{<t}$, но не от последующего токена. В общей факторизации
$z_{<t}$ обозначает весь предшествующий префикс; ограниченный декодер из примера
получает не более последних $C=4$ предшествующих токенов. Зафиксированное
разбиение вводит аналогичное ограничение для эксперимента: в этом запуске
отложенные для теста документы не могут влиять на обучение токенизатора,
обновления параметров или выбор состояния по валидации.

## Не смешивайте позицию в последовательности с этапом процесса

- $P_\theta$ — распределение вероятностей, заданное декодером.
- $\theta$ содержит все обученные значения параметров, выбранные по функции
  потерь на валидации.
- $z_{1:T}$ — одна последовательность от первого токена до токена $T$.
- $T$ — число токенов, совместная вероятность которых вычисляется.
- $\prod_{t=1}^{T}$ перемножает по одному условному множителю в каждой позиции.
- $t$ — текущая позиция токена.
- $z_t$ — наблюдаемый токен в этой позиции.
- $z_{<t}$ — предшествующий каузальный префикс в общей факторизации; в этом
  примере декодеру передаются не более последних $C=4$ предшествующих токенов.

Номер шага обучения — не $t$. Один шаг обновляет $\theta$ по мини-пакету, а $t$
нумерует токен внутри факторизации языковой модели.

## От короткого частотного контекста к авторегрессионным LLM на основе Transformer

Биграммная модель на основе частот оценивает следующий токен по одному
предшествующему токену: она не переносит статистические закономерности через
обученные признаки и не использует более длинный каузальный префикс.

[A Neural Probabilistic Language Model](https://www.jmlr.org/papers/volume3/bengio03a/bengio03a.pdf)
подтверждает это ограниченное утверждение. Бенжио и соавторы описывают, как
традиционные n-граммные модели обобщают по коротким перекрывающимся
последовательностям, и показывают нейронную вероятностную функцию с обучаемыми
распределёнными представлениями слов, результаты которой улучшаются при
увеличении контекста; их модель не является ни Transformer, ни полным процессом
из этого курса.

[Attention Is All You Need](https://arxiv.org/pdf/1706.03762) подтверждает
следующее архитектурное ограничение. Васвани и соавторы задают Transformer и
маскируют самовнимание декодера так, чтобы позиция не могла обращаться к
последующим позициям; опубликованная ими архитектура состоит из кодировщика и декодера и не
задаёт правила работы с данными, контрольными точками или генерацией в этом
курсе.

[Language Models are Few-Shot Learners](https://arxiv.org/pdf/2005.14165)
показывает следующий этап масштабирования LLM. Браун и соавторы обучают GPT-3 —
авторегрессионную языковую модель на основе Transformer с 175 миллиардами
параметров, построенную по архитектуре GPT-2, — и оценивают задачи с нулевым,
одним и несколькими примерами без обновления параметров по градиенту и без
дообучения. Результаты по масштабу и возможностям этой модели нельзя переносить
на небольшой учебный запуск.

Нейронные языковые модели научились распределённым признакам токенов и
вероятностным функциям, использующим более длинный контекст; Transformer добавил
маскированное самовнимание, а более поздние авторегрессионные языковые модели на
основе Transformer масштабировали ту же цель обучения.

В завершающем примере курса объединены обучение токенизатора только по обучающей
выборке, каузальные обновления по следующему токену, выбор состояния по
валидации, итоговая оценка после выбора, точное сохранение и восстановление
контрольной точки и генерация с явным состоянием. Это локальные правила проверки,
а не требования цитируемых статей.

Сопоставьте биграммную модель со сглаживанием $\alpha=1$, обученную только по
обучающей выборке, и каузальный декодер с контекстом из четырёх токенов,
выбранный по валидации, на одних и тех же целевых позициях из тестовой выборки.
Измеренная разница относится к этому примеру и не доказывает причинного влияния
контекста или внимания.

Частотные n-граммы служили сильной базовой моделью с коротким контекстом;
обученные распределённые признаки и маскированное самовнимание сделали
возможной обучаемую обработку более длинного контекста, а масштабированные
авторегрессионные модели на основе Transformer стали одним из основных семейств современных LLM.
Завершающий пример показывает границы ответственности полного процесса в
масштабе, позволяющем проследить каждую деталь, и не превращает один небольшой
выигрыш по функции потерь во всеобщий вывод о качестве.

Сравнение в программе намеренно узкое: однотокенный частотный контекст
сопоставляется с каузальным декодером, использующим контекст из четырёх токенов,
на этом зафиксированном корпусе. Более низкое значение функции потерь —
проверяемый результат именно этого примера. Оно не устанавливает всеобщего превосходства одной архитектуры и
не подтверждает полезное качество генерации.

## Соберите готовые API, не копируя алгоритмы

<code>run_capstone</code> сначала загружает и проверяет корпус и манифест разбиения.
Функция обучает BPE по обучающей выборке, кодирует каждый документ отдельно, не
склеивая их границы, обучает по тем же обучающим токенам биграммную модель со
сглаживанием $\alpha=1$ и строит отдельные наборы каузальных мини-пакетов для
обновлений, валидации и итоговой оценки.

Два запуска декодера получают одинаковую инициализацию и одинаковое зерно,
задающее порядок мини-пакетов. Каждый выполняет все $32$ обновления. Реализация
побитово сравнивает все события обучения, измерения функции потерь в контрольных
точках, значения моментов оптимизатора, выбранный шаг и значения параметров
модели. Только после совпадения повторных запусков и фиксации
выбранного по валидации состояния программа формирует тестовые мини-пакеты.
Объект <code>FinalEvaluator</code> этого запуска использует своё локальное право
доступа один раз. Это проверяемая программой граница внутри данного запуска, а не
утверждение, будто весь репозиторий не позволяет другому коду читать корпус.

Выбранная модель и состояние оптимизатора на шаге $32$ сохраняются в одной
версионированной контрольной точке. Повторное кодирование загруженной контрольной
точки должно воспроизвести сохранённые байты; побитово должны совпасть
восстановленные модель и оптимизатор, ранги BPE-слияний, номер шага и состояние
генератора псевдослучайных чисел. Для отдельной пробы <code>At</code> все логиты
тоже должны совпасть побитово. Лишь после этого загруженная модель выполняет
генерацию из промпта <code>A</code> двумя способами, начиная с одинакового состояния
генератора: с KV-кэшем и с повторным вычислением всего префикса на каждом шаге.

## Проследите процесс: поздние результаты не влияют на ранние этапы

В начале схемы зафиксированы роли документов, а токенизатор обучается только по
обучающей выборке. Затем каузальные окна поступают в декодер; выбранное по
валидации состояние расположено перед локальной границей доступа к тестовым
данным, выделенной двойной рамкой. В этом запуске значение функции потерь на
тестовой выборке не влияет ни на обновление параметров, ни на выбор состояния.

На двух последних этапах проверяются разные виды равенства. Повторное кодирование
восстановленной контрольной точки даёт те же байты; модель, оптимизатор,
токенизатор, шаг и состояние генератора псевдослучайных чисел совпадают точно, а
логиты для пробы <code>At</code> — побитово. Генерация с KV-кэшем из промпта
<code>A</code> совпадает с путём по полному префиксу по решениям о токенах и
конечному состоянию генератора. Перед тремя выборами токена длины сохранённых
префиксов равны $1$, $2$ и $3$ токенам. При заполнении KV-кэша единственный
токен промпта даёт логиты для первого выбора. Затем программа ещё дважды
вызывает декодер, подавая сначала первый, затем второй сгенерированный токен;
эти вызовы дают логиты для второго и третьего выборов. Путь с KV-кэшем вычисляет
$1+2+3=6$ значений оценок внимания; для того же расписания префиксов эталонный
расчёт по полному префиксу даёт $1^2+2^2+3^2=14$ значений.

2. Сколько параметров декодера получает обновления?
3. Какие данные определяют выбор шага $32$?

повторение воспроизводимым, но не превращает тестовые данные в допустимое
основание для выбора. Здесь состояние сначала фиксируется, тестовые мини-пакеты
формируются после этого, а локальный объект оценки данного запуска регистрирует
один доступ.

## Теперь весь декодер в ваших руках

Теперь все части курса участвуют в одной работающей программе: зафиксированный
двуязычный корпус превращается в BPE-токены и каузальные пакеты; валидационная
выборка определяет состояние декодера до передачи тестовых пакетов локальному
объекту итоговой оценки; байты контрольной точки и состояние точно
восстанавливаются; отдельная проба <code>At</code> побитово воспроизводит логиты;
генерация с кэшем из <code>A</code> возвращает декодированный текст.

Так завершается запланированный путь к современной декодерной LLM в учебном
масштабе. Теперь можно изменить одну часть с чёткими границами — увеличить
контекст или ширину блока, задать другой бюджет токенизатора либо заменить сэмплер — и точно
определить, какие свидетельства о данных, математике, обучении, оценке,
сохранении состояния и выводе потребуется получить заново.
