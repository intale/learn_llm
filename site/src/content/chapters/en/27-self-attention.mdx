## Predict which value each query will retrieve

Continue directly from Chapter 26. Its three projections produced

$$
Q=\begin{bmatrix}0&3\\2&-1\end{bmatrix},\quad
K=\begin{bmatrix}3&0\\-1&2\end{bmatrix},\quad
V=\begin{bmatrix}3&-3\\1&3\end{bmatrix}.
$$

There is one batch with two token positions. The query/key feature width and
value width are both two, so $Q,K,V\in\mathbb{R}^{1\times2\times2}$.

Before calculating a softmax, predict which value each query will retrieve.
The first query produces the two dot products

$$
q_0K^\top=[0,6],
$$

so it should favor $v_1=[1,3]$. The second produces

$$
q_1K^\top=[6,-4],
$$

so it should strongly favor $v_0=[3,-3]$. The signs and relative gaps matter;
normalization will turn each score row into retrieval weights.

{/* chapter-section:formula */}

## Score, scale, normalize, and mix

One unmasked scaled dot-product attention head follows

$$
A=\operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right),\quad O=AV
$$

For this fixture, the raw and scaled score matrices are

$$
QK^\top=\begin{bmatrix}0&6\\6&-4\end{bmatrix},\qquad
\frac{QK^\top}{\sqrt{2}}\approx
\begin{bmatrix}0&4.242641\\4.242641&-2.828427\end{bmatrix}.
$$

Softmax runs across key positions independently for each query:

$$
A\approx
\begin{bmatrix}
0.014166&0.985834\\
0.999151&0.000849
\end{bmatrix},\qquad
\sum_j A_{ij}=1.
$$

The first weighted value mixture is

$$
o_0
=0.014166[3,-3]+0.985834[1,3]
\approx[1.028332,2.915004].
$$

The second is

$$
o_1
=0.999151[3,-3]+0.000849[1,3]
\approx[2.998303,-2.994908].
$$

Thus

$$
O\approx
\begin{bmatrix}
1.028332&2.915004\\
2.998303&-2.994908
\end{bmatrix}.
$$

## Keep query rows and key columns separate

- $Q$ contains one query row per token position: what should this position retrieve?
- $K$ contains the candidate key rows: how can each position be matched?
- $d_k$ is the shared query/key width.
- $A$ contains one normalized retrieval row for every query.
- $V$ contains the value rows whose content is mixed.
- $O$ contains one resulting mixture per query position.
- $B$ is the batch size, $T$ the token count, and $d_v$ the value width.

The complete shape rule is

$$
Q,K\in\mathbb{R}^{B\times T\times d_k},\quad
V\in\mathbb{R}^{B\times T\times d_v},\quad
A\in\mathbb{R}^{B\times T\times T},\quad
O\in\mathbb{R}^{B\times T\times d_v}.
$$

For fixed batch $b$ and query position $i$, the key position $j$ varies inside
one probability row:

$$
S_{bij}=\frac{q_{bi}\cdot k_{bj}}{\sqrt{d_k}},\qquad
A_{bij}=\frac{\exp(S_{bij})}{\sum_{r=0}^{T-1}\exp(S_{bir})}.
$$

That row sum makes $A_{bij}$ a retrieval weight. It is not a calibrated
probability that a token or claim is correct.

Vaswani et al. motivate the denominator with a bounded argument: if query and
key components are independent with mean zero and variance one, their dot
product has variance $d_k$. Dividing by $\sqrt{d_k}$ counteracts that variance
growth in the argument. This is not a universal theorem, an overflow guarantee,
or proof that the scale is an optimal temperature.

## From recurrent context to all-position retrieval

This is neural-attention history on the road to modern LLMs, not programming-
language history.

[Bahdanau, Cho, and Bengio, *Neural Machine Translation by Jointly Learning to Align and Translate*](https://arxiv.org/abs/1409.0473)
describe how a basic recurrent encoder-decoder may struggle when a whole source
sentence must fit into one fixed-length vector. Their proposed model scores the
previous decoder state against each encoder annotation, applies softmax, and
mixes annotations into a new context for that decoder step.

A basic recurrent encoder-decoder can compress an entire source sentence into
one fixed-size vector, making long-range source details difficult to preserve;
additive attention instead retrieves a new weighted source context for each
decoder step but retains recurrent alignment steps between two sequence
streams.

Bahdanau, Cho, and Bengio describe the possible fixed-length-vector bottleneck
of a basic encoder-decoder and compute each new context as a softmax-weighted
sum of encoder annotations scored against the previous decoder state.

Calling that learned scoring function *additive attention* follows the later
retrospective classification used by Vaswani and colleagues. The earlier paper
does not use this chapter's query, key, and value notation, scaled dot products,
or same-sequence score grid.

[Vaswani et al., *Attention Is All You Need*](https://arxiv.org/abs/1706.03762)
define scaled dot-product attention with the chapter formula, pack multiple
queries into matrices, and define self-attention as relating positions in one
sequence.

The Transformer uses scaled dot-product attention and packs many queries into
matrices; self-attention compares positions from the same sequence so one layer
can form its full score grid together.

Vaswani et al. define scaled dot-product attention as softmax-normalized scaled
query-key products applied to values, describe packed simultaneous queries, and
define self-attention as relating positions within one sequence.

Each decoder self-attention head turns learned queries and keys into retrieval
probabilities, then mixes learned values; a causal decoder additionally masks
future key positions before normalization.

Packing positions lets one layer form its score grid together. It does not make
total work constant, and it does not make autoregressive token generation
parallel. The tiny executable contrast records two recurrent decoder steps and
four score cells for this fixture's $2\times2$ grid; it is a structural example,
not a hardware benchmark:

1. Compute all four entries of $QK^\top$ for the frozen fixture.
2. Predict which key each query favors before applying softmax.
3. Explain why each row of $A$ sums to one instead of each column.
4. Predict the output shape for $Q,K\in\mathbb{R}^{4\times7\times3}$ and $V\in\mathbb{R}^{4\times7\times5}$.
5. Predict the attention probability and output when there is one token with value $[5,-2]$.
6. Decide what happens if the same two token positions are swapped in $Q$, $K$, and $V$.
7. Predict the probabilities when the two key rows are equal.
8. Identify which information is visible here but invalid during causal decoder training.
9. Explain what the two-step versus four-score historical fixture does and does not claim.

## Mask future keys next

The cumulative decoder can now turn one projected query/key/value triplet into
the output of an unmasked attention head. Chapter 28 will exclude future key
positions before each score row is normalized.

The head already preserves batch and query-position axes and returns both the
inspectable probability matrix and mixed values. It is not yet safe for
autoregressive decoding: every query can read every key. Causal masking is the
next boundary; positional information, multiple heads, output projection,
residual wrapping, and cached decoding remain later chapters.
