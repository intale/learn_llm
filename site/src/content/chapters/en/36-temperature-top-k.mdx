## Start with four logits and make every choice visible

The decoder supplies final-position logits in token-ID order:
$[0,1,1,2]$. Their stable descending-logit order, with ascending token ID as
the tie-breaker, is $[3,1,2,0]$. Token $3$ is unambiguously first. Tokens $1$
and $2$ have equal logits, so this
implementation places the smaller ID first. That local rule makes the tied
candidate order deterministic.

First keep all four tokens and vary only the positive temperature. At
$\tau=0.5$, token $3$ receives probability $0.775803492574$; at $\tau=1$, it
receives $0.534446645389$; at $\tau=2$, it receives $0.387455619000$. Lower
temperature sharpens existing logit differences. Higher temperature flattens
them. Neither changes the stable rank.

Now set $\tau=1$ and $k=2$. The rank-retained order is $[3,1]$. Token $1$ stays
inside the tied boundary and receives $\widehat q_1=0.268941421370$; token $2$
is removed and receives exactly $\widehat q_2=0$. Token $3$ receives
$\widehat q_3=0.731058578630$. The stored probabilities sum to $1$.

Rank retention does not guarantee positive floating-point probability. For
logits $[2,2,1]$, temperature `f64::MIN_POSITIVE`, and $k=3$, stable ranking
retains $K_3=[0,1,2]$. The two maximum-logit tokens receive stored probabilities
$0.5$ and $0.5$. Token $2$ is still rank-retained, but its max-shifted
exponential weight rounds to exact zero, so $\widehat q_2=0$ and the positive
representable support is $S_{\tau,3}^{(\mathrm{f64})}=\{0,1\}$.

With $k=3$, SplitMix64 seed $36$ produces the reproducible sequence
$[3,2,2,2,3,3,3,3]$. For example, the second unit draw is
$u=0.338833394523$. It lies in token $2$'s half-open interval
$[0.211941557617,0.423883115234)$, so that draw selects token $2$.

## Filter the candidate set, then renormalize

For finite logits, finite positive temperature, and $1\le k\le V$, real
arithmetic defines the ideal probability $q_i^{(\tau,k)}$. The implementation
stores $\widehat q_i^{(\tau,k)}$ in `f64`, so its positive sampling support can
be a strict subset of the rank-retained set:

$$
q_i^{(\tau,k)}=\frac{\mathbf{1}[i\in K_k]\exp(\ell_i/\tau)}{\sum_j\mathbf{1}[j\in K_k]\exp(\ell_j/\tau)},\quad \lvert K_k\rvert=k,\quad S_{\tau,k}^{(\mathrm{f64})}=\{i\in K_k\mid\widehat q_i^{(\tau,k)}>0\}\subseteq K_k
$$

The implementation subtracts the largest retained scaled logit before applying
the exponential. In real arithmetic that shift preserves probability ratios and
prevents a large common offset from causing avoidable overflow. In `f64`, however,
a sufficiently small retained exponential weight can still round to exact zero.
Every removed ID has stored probability zero, but the converse is false: a stored
zero can also belong to $K_k$. Positive support therefore uses the stored
$\widehat q_i>0$ test, not rank membership alone.

Temperature must be strictly positive. The mathematical limit
$\tau\to0^+$ helps explain concentration toward a unique maximum, but literal
$\tau=0$ would divide by zero. Greedy decoding is therefore a separate policy:
it validates the same logits, chooses the token ID at the first stable rank, and
consumes no random draw. Stochastic $k=1$ chooses the same ID but deliberately consumes one
draw, because it still follows the sampling policy.

## Keep logits, candidates, and probabilities distinct

- $q_i^{(\tau,k)}$ is token $i$'s ideal real-arithmetic probability after all
  three operations.
- $\widehat q_i^{(\tau,k)}$ is the probability actually stored for token $i$ in
  `f64` after max-shifted `f64` exponentiation and normalization.
- $S_{\tau,k}^{(\mathrm{f64})}$ is the positive representable sampling support:
  retained IDs whose stored probability is strictly greater than zero.
- $\tau$ is a finite positive temperature. Lower values enlarge scaled-logit
  gaps and concentrate the probability distribution; higher values shrink those
  gaps and flatten the distribution.
- $k$ is the exact number of retained token IDs.
- $V$ is the vocabulary size, so the valid candidate count satisfies
  $1\le k\le V$.
- $K_k$ is the rank-retained top-$k$ set and always has exactly $k$ IDs. Equal
  logits use ascending token ID here.
- $\mathbf{1}[i\in K_k]$ is $1$ for a retained ID and $0$ for a removed ID.
- $\ell_i$ is the decoder logit for token $i$ at the final prefix position.
- $i$ names the candidate whose final probability is being described.
- $j$ ranges over the vocabulary in the denominator.
- $\exp$ is positive in real arithmetic. Its max-shifted `f64` result can round
  to zero for a sufficiently negative represented gap.

These names protect an important boundary. A logit is an unrestricted decoder
score, stable rank determines membership in $K_k$, and a stored probability
determines membership in $S_{\tau,k}^{(\mathrm{f64})}$. Temperature changes score
gaps before normalization. Top-k changes which terms are retained. Floating-point
evaluation can narrow positive support after that rank decision.

The sampler inspects stored probabilities in ascending token-ID order and skips
every exact zero. In the ordinary fixture, a unit draw $u$ selects token $i$ from
its recorded half-open interval $[a_i,b_i)$ when $a_i\le u<b_i$. An exact-zero
probability certainly owns no interval and cannot be selected. Because cumulative
endpoints are also represented in `f64`, this chapter does not claim that every
positive stored probability necessarily receives a nonempty reachable interval
for every possible vocabulary. The final positive candidate handles any tiny
endpoint discrepancy from floating-point summation without reviving a zero-
probability token.

## From constrained search to open-ended LLM sampling

Likelihood-maximizing beam decoding is useful when a source tightly constrains
the target, but open-ended continuation admits many plausible futures; beam
output can become generic or repetitive, while unrestricted sampling can admit
an unreliable low-probability tail.

[Fan, Lewis, and Dauphin](https://arxiv.org/pdf/1805.04833) make that open-ended
boundary concrete. Fan, Lewis, and Dauphin sample at each step from the ten most
likely words, tune a generation-time softmax temperature, and report that this
task-bounded strategy works better for their open-ended stories than beam search,
while unrestricted random sampling can introduce damaging unlikely words.

[The GPT-2 report](https://cdn.openai.com/better-language-models/language-models.pdf)
provides two concrete task-specific sampling settings. The GPT-2 report uses
top-k random sampling with $k=2$ for one summarization setup and $k=40$ for open
WebText continuations, showing truncated stochastic decoding in large Transformer
language-model practice without claiming one $k$ is universal.

[Holtzman and colleagues](https://arxiv.org/pdf/1904.09751) examine the trade-off
directly. Holtzman and colleagues compare maximization and stochastic decoders
on GPT-2, define top-k as sampling from the $k$ highest-probability tokens after
renormalization, give the temperature-scaled softmax, and show why flat and
peaked contexts make a fixed $k$ an imperfect compromise.

Open-ended story systems combined softmax temperature with top-k sampling,
GPT-2 used top-k for summaries and long continuations, and later GPT-2 analysis
made the truncation and renormalization trade-off explicit while showing why one
fixed $k$ cannot fit every context.

Controlled stochastic decoding turns an autoregressive LLM distribution into
an adjustable diversity-versus-concentration distribution. Restoring the same
random-generator state while preserving deterministic tie-breaking and interval
traversal lets the sampler replay its choices. Later methods can replace the
fixed candidate count without changing the decoder logits.

Top-k is therefore a clear first controlled stochastic decoder, not a universal
quality guarantee, a hallucination defense, or the endpoint of decoding
research. Stable token-ID ties, seed replay, invalid-setting behavior, EOS, and
context stops are this implementation's reproducibility rules rather than
claims about the cited systems.

The executable contrast measures the mechanism on the chapter's four logits.
Greedy chooses token $3$ without advancing the random generator. At $\tau=1$,
fixed $k=3$ keeps IDs $[3,1,2]$: those candidates held
$0.927670511871$ of the full-softmax mass, while truncation removes
$0.072329488129$ before renormalization. That measurement does not determine
which policy produces better text; it makes the fixed-cardinality boundary
visible.

## Validate first, rank stably, and advance the random stream once

`SamplingMode::Greedy` and `SamplingMode::TemperatureTopK` are explicit choices.
Both reject empty or nonfinite logits. The stochastic policy additionally rejects
nonfinite or nonpositive temperature and any $k$ outside $1\le k\le V$. All
validation happens before the SplitMix64 state changes.

All three public operations start with the same calculation: validate the inputs,
rank finite logits by descending value and ascending token ID, retain the
requested candidate count, and turn their logits into stored `f64` probabilities.
`sample_next_token` returns only the selected token ID, optional
unit draw, and selected half-open interval. It does not build the token-by-token
candidate records or the rank-ordered retained-ID list used for inspection.
`sample_next_token_with_trace` uses the same calculated probabilities and the same
interval-selection code, but builds that full inspectable distribution before any
draw. `sampling_distribution` builds the distribution without drawing. The
ordinary call still needs temporary arrays of ranked token IDs and probabilities
to perform the algorithm; it avoids only the additional inspection records.

In an inspectable distribution, candidates appear in token-ID order and the
separate retained-ID list appears in stable rank order. Removed IDs have exact
zero probability after max-shifted normalization, and a retained ID may also
have exact zero when its represented weight underflows. Categorical selection
skips stored zero probabilities in ascending token-ID order; that exclusion is
the guarantee, not a claim that every positive stored value must own a nonempty
reachable interval. Greedy consumes no draw; every valid stochastic call
consumes exactly one unit draw, including top-k with $k=1$.

`generate_uncached` retains the complete prefix. Before each decoder call it

retains the complete inspectable candidate distribution for each generated token.
EOS is included before the loop stops. A valid capacity-$2$ prefix can therefore
emit a next token even though the resulting length-$3$ sequence cannot be
submitted for another call.

## Preserve this uncached sequence when generation becomes incremental
