## Give source documents their roles before learning

A tokenizer can learn which pieces of text to merge, and a model can learn weights
that help it predict text. Measuring either system only on the observations used
to fit it leaves an unanswered issue: the result may depend on those particular
observations. It does not, by itself, establish how the system behaves on new text.
We therefore decide which source text may fit the system and which text will serve
other purposes before learning begins.

A **corpus** is a collection of source documents. A **source document** is one
complete text whose start and end we preserve as a **document boundary**. In this
chapter's corpus, a complete scene in one language is one document. The single
file `rust/data/tiny-bilingual-corpus.json` holds twelve JSON records, so the file
itself is not the document unit. Each record has a language, a provenance group,
and the text. Its **document ID** is the stable label used to name that record in
the split; the label does not prove that its text is independent of other text.

A **partition** is the subset of corpus documents assigned to one role: training,
validation, or test. A **provenance group** joins documents known to contain
related source content. Here
the English and Russian versions of the same scene share one group. They have
different IDs and different text, but a translation in training can still expose
content from its held-out partner. Whole documents and their known groups must
therefore stay in one role.

Chapter 1 used a fixed mapping from text units to IDs. This chapter prepares the
boundary needed when the mapping itself will be learned. The three roles separate
fitting, choosing, and reporting:

<div id="ch02-role-table">

| Role | What its documents are used for |
| :--- | :--- |
| Training | Fit learned state: byte-pair encoding (BPE) pair counts and merge rules in Chapter 3, then model weights in later chapters. |
| Validation | Compare choices fitted on training data, or select a checkpoint: a saved model state from a particular training step. |
| Test | Report performance after fitting and selection are complete. A test result used to make another choice becomes part of selection. |

</div>

Validation and test are **holdout data** because they stay outside fitting. They
can still supply evaluation statistics, such as a measured error. Computing such
a statistic is different from adding their pair counts to a tokenizer or using
them to compute weight-update signals, called gradients. Validation influences the chosen system,
so it is not untouched once we use it to choose. This chapter assigns the roles;
it does not fit a tokenizer or model or compute a performance score.

The membership rule is easiest to see with a separate, six-document example.
Let its complete corpus have IDs `doc-01` through `doc-06`. The following lists
are rejected:

```text
train      = [doc-01, doc-02]
validation = [doc-03, doc-04]
test       = [doc-04, doc-05]
```

The lists contain six positions but only five distinct IDs. `doc-04` occupies
both a validation position and a test position; `doc-06` occupies none. Their
union, meaning all IDs found in any role, therefore omits `doc-06`. Their pairwise
intersections, meaning IDs shared by two roles, expose the other failure:
validation and test share `doc-04`, while training shares no ID with either role.
Having the intended number of listed positions was not enough.

Keep training and validation as written and repair the test list:

```text
train      = [doc-01, doc-02]
validation = [doc-03, doc-04]
test       = [doc-05, doc-06]
```

Now all six corpus IDs appear once. The union covers `doc-01` through `doc-06`,
and all three pairwise intersections are empty. This repair establishes complete,
separate membership for the six named documents. It does not establish that their
texts are unrelated or that they represent every kind of future text. The
executable twelve-document corpus later in this lesson is a different example.

## Express coverage and separation as sets

Treat the corpus and each role's membership as sets of whole documents. The
repaired example satisfies this statement:

$$
\mathcal{D}=\mathcal{D}_{tr}\mathbin{\dot\cup}\mathcal{D}_{va}\mathbin{\dot\cup}\mathcal{D}_{te},\quad \mathcal{D}_{a}\cap\mathcal{D}_{b}=\varnothing\;(a\ne b)
$$

The equality says that the three sets cover the corpus. The dotted union also
requires that no document belongs to different roles. The intersection clause
states that separation explicitly for any two distinct role labels. In the
rejected example, validation and test shared `doc-04`, so that intersection was
not empty; the missing `doc-06` also broke coverage.

The manifest stores ordered ID lists, whereas the formula describes sets. A set
forgets repeated positions within one list and forgets order altogether. Listing
the same training ID twice cannot be justified by this formula, even if the set
of training IDs looks unchanged. Reversing a list likewise leaves its set
membership unchanged while changing its iteration order. The implementation
checks those list properties separately. The formula also does not require
nonempty roles, intact provenance groups, unchanged input bytes, or representative
sampling.

## Read each symbol in the split statement

<div id="ch02-symbol-table">

| Symbol | Meaning in this chapter |
| :--- | :--- |
| $\mathcal{D}$ | The corpus considered as a set of whole source documents. |
| $\mathcal{D}_{tr}$ | Training documents used to fit tokenizer rules and model weights. |
| $\mathcal{D}_{va}$ | Validation documents used to compare training-fitted choices or select a saved model state. |
| $\mathcal{D}_{te}$ | Test documents reserved for reporting after fitting and selection are complete. |
| $tr,va,te$ | The labels for the training, validation, and test roles. |
| $\dot\cup$ | Disjoint union: the sets cover the corpus and no document belongs to different roles. |
| $a,b$ | Two role labels, each chosen from $tr$, $va$, and $te$. |
| $\cap$ | Set intersection: the documents that belong to both compared sets. |
| $\varnothing$ | The empty set, containing no shared document. |
| $a\ne b$ | The intersection condition applies when the two role labels are different. |

</div>

These symbols describe membership and use, not a preferred split percentage. The
appropriate amount of text for each role depends on the available corpus and the
evaluation goal. The later eight/two/two counts in this chapter are document counts
chosen for a small teaching example; they are not byte counts, token counts, or a
universal ratio.

## Preserve the source boundary behind each ID

Separating fitting from assessment predates modern LLMs. Stone's 1974 paper studies
[cross-validatory choice and assessment](https://doi.org/10.1111/j.2517-6161.1974.tb00994.x).
For language modeling, the unit that carries context also matters. Merity and
colleagues introduced [WikiText](https://arxiv.org/abs/1609.07843) using article
text to support longer dependencies. At larger scale, Brown and colleagues
investigated [training-data overlap with development and test benchmarks](https://arxiv.org/abs/2005.14165).
These sources motivate attention to assessment and source context; they do not
prescribe this course's fixed bilingual split.

The existing Rust contrast shows one way a holdout label can conceal shared
source context. It takes the single sentence `north star glows softly` and calls
`overlapping_word_windows("north star glows softly", 3)`. The two resulting windows
are `["north", "star", "glows"]` and `["star", "glows", "softly"]`.
`shared_words` reports `["star", "glows"]` in the first window's order:

  caption="Two overlapping windows from one source sentence"
  captionId="ch02-overlapping-excerpts-caption"

If we name those windows separately and put one in training and the other in
validation, the IDs differ but source context crosses the role boundary. The
problem is their derivation from the same sentence. Two unrelated documents
using a common word do not, for that reason alone, demonstrate this leakage.
Here, **data leakage** means that information available to fitting crosses a
boundary meant to keep assessment separate from that fitting.

Assign whole source documents and known provenance groups first. Fit tokenizer
statistics only on training documents, freeze the learned rules, and apply those
rules separately to text in each role. Any later token windows must remain inside
an original document and retain its role. Renaming excerpts cannot replace that
order. This prevents the demonstrated overlap path; it is not a claim that every
historical experiment leaked or that every overlap improves every score.

The fixed manifest makes assignments repeatable, and retained corpus order makes
later iteration and printed evidence repeatable. Neither property establishes
statistical independence. Exact duplicate rejection does not detect every
near-duplicate or copied passage; known group labels do not discover every
unrecognized relationship. A deterministic split may still sample a narrow
topic range or fail to represent text encountered later.

The 64-bit FNV-1a value is a limited drift check. A mismatch reports a different
checksum. A match reports only that recomputation produced the recorded value:
collisions are possible, so it does not prove byte identity, authorship, licensing,
or cryptographic authenticity. The corpus README records the teaching text's
origin separately.

## Follow all twelve documents in the fixed corpus

The corpus represents six scenes in English and Russian. Each scene contributes
two documents to one `pair-*` provenance group. Training contains, in source order,
the river-dawn, clock-shop, rain-library, and bee-garden pairs: eight documents in
four groups. Validation contains the night-station pair: two documents in one
group. Test contains the winter-window pair: two documents in one group.

The figure lists every exact ID, language, and group. Its three lists are peer
sets, not stages through which a document moves. Read each card as one whole
document and read the cards within each role in corpus source order:

<CorpusPartitionsDiagram labels={diagramLabels} />

For example, `en-night-station` has language `en` and `ru-night-station` has
language `ru`; both have group `pair-night-station` and both belong to validation.
Different languages do not make the shared scene independent. The same pairing
rule holds for `pair-river-dawn`, `pair-clock-shop`, `pair-rain-library`,
`pair-bee-garden`, and `pair-winter-window`. Every corpus ID appears in exactly
one role, with eight training documents and two documents in each holdout role.

This is an original, public teaching corpus small enough to inspect. It supports
repeatable examples, not a claim of useful real-world language-model quality.
Rerunning a known test result checks for regression; it does not supply a fresh,
independent estimate of generalization each time.

## Give BPE only the training documents

Chapter 3's BPE trainer uses `partitions.training_documents()`: the eight whole
training documents. It starts a separate byte-token sequence for each document
and counts adjacent pairs inside that sequence. The last byte of one document
does not become adjacent to the first byte of the next. Validation and test
supply no pair counts or learned merge rules.

After fitting, the learned rules can be frozen and applied to held-out text
without learning from it. Later token windows must also stay within original
document boundaries and keep the document's role. This preserves both boundaries:
which text fits learned state, and which text belongs to one source.

The same responsibilities continue into model training: training fits weights,
validation guides choices, and test reports after selection. Chapter 34 later
demonstrates that order with a local evaluator inside one execution. Its gate
cannot enforce unique access across all callers or later executions, and its
caller-supplied provenance labels do not independently establish data history.
The later deliberately chosen, known comparison remains regression evidence,
not an untouched generalization estimate. The boundary introduced here makes
those later claims precise without pretending that a small fixed corpus proves
more than it does.
