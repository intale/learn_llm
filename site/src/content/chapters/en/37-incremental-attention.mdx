The fixture has one batch, model width $D=4$, $H=2$ heads, head width $d_h=2$,

## Append along the position axis

For attention layer $\ell$, the cache transition is

$$
K^{(\ell)}_{1:t}=[K^{(\ell)}_{1:t-1};k^{(\ell)}_t],\quad V^{(\ell)}_{1:t}=[V^{(\ell)}_{1:t-1};v^{(\ell)}_t]
$$

The semicolon means concatenate along the sequence-position axis. The new key
$k^{(\ell)}_t$ has already received RoPE for its absolute position. The new
value $v^{(\ell)}_t$ has been projected and split into heads but is not rotated.
Queries are needed only for the current calculation, so there is no query cache
in this boundary.

The implementation uses a zero-based offset equal to the old cache length. The
formula uses conventional one-based prefix notation, so mathematical position
$t$ is one greater than that offset.

{/* chapter-section:symbol-glossary */}

## Keep layer, logical length, and capacity separate

- $K^{(\ell)}_{1:t}$ is layer $\ell$'s rotated key prefix after the append.
- $V^{(\ell)}_{1:t}$ is the same layer's value prefix after the append.
- $\ell$ identifies the decoder-block attention layer that owns the state.
- $t$ identifies the newest position in one-based mathematical prefix notation.
- $1:t$ includes every retained position through the newest one.
- $K^{(\ell)}_{1:t-1}$ and $V^{(\ell)}_{1:t-1}$ are the unchanged earlier rows.
- $k^{(\ell)}_t$ and $v^{(\ell)}_t$ are the one-row candidate pair.
- $[A;B]$ means append $B$ after $A$ along the position axis.

The physical buffers have shape $[B,H,C,d_h]$, where $B$ is batch size, $H$
is head count, $C$ is fixed capacity, and $d_h$ is head width. A logical
snapshot has shape $[B,H,t,d_h]$. Reset changes $t$ to $0$ without changing
$C$ or allocating replacement buffers.

## From causal attention to managed LLM inference state

Causal Transformer attention lets the newest decoder position read the known prefix, but a naive generation loop can rebuild every earlier key and value projection on every step even though those earlier layer states are unchanged.

[Attention Is All You Need](https://arxiv.org/pdf/1706.03762) supplies the
causal reference. Vaswani and colleagues define scaled dot-product attention, describe an autoregressive decoder that emits one element at a time, and mask decoder self-attention so a position can use only the known prefix; the paper does not specify KV caching or RoPE.

[Fast Transformer Decoding: One Write-Head is All You Need](https://arxiv.org/pdf/1911.02150)
makes the reuse boundary explicit. Shazeer's incremental multi-head self-attention takes previous key and value tensors, appends the current projected pair, and returns the enlarged tensors; its analysis identifies repeatedly loading those tensors as a memory-bandwidth bottleneck before proposing multi-query attention.

[Efficient Memory Management for Large Language Model Serving with PagedAttention](https://arxiv.org/pdf/2309.06180)
continues the road into modern serving. Kwon and colleagues describe sequential LLM generation in which earlier key and value vectors are cached and only the newest pair is computed, then organize dynamically growing KV caches as logical blocks mapped to non-contiguous physical memory.

Incremental Transformer decoding retained earlier per-layer key and value tensors, appended one new pair, and made repeated KV movement an explicit performance concern; later LLM serving systems treated the dynamically growing KV cache as a major memory-management object.

A layer-local KV cache avoids reprojecting the same earlier states while the newest query still attends across the complete retained prefix; model-wide cached generation therefore needs one compatible cache for every decoder block.

Move from complete-prefix recomputation toward one-step attention that retains each layer's earlier key and value state.

The road to modern LLM inference starts from causal prefix attention, makes per-step KV reuse explicit, and later manages that growing state as a serving-memory problem. This course's fixed capacity, exact layout, reset behavior, RoPE offset rule, layer binding, and typed errors are local correctness policies rather than claims made by those papers.

## Bind the state, calculate completely, then commit

`LayerKvCache::new` takes the actual attention layer. It records batch, model,
head, capacity, and head-width configuration; owns fixed key/value buffers; and
privately retains the exact parameter-node and RoPE identity. Equal dimensions
are therefore not enough to reuse stale state from rebuilt weights or a
different positional configuration.

`forward_incremental` accepts exactly $[B,1,D]$. Inside its own no-gradient
scope it projects the new row, splits heads, rotates Q and K at the old cache
length, computes stable weights shaped $[B,H,1,t+1]$, mixes the retained and
candidate values, merges heads, and applies the existing output projection.
Only a fully assembled result permits the key/value copy and length increment.

<RustSource

Across prefix lengths $1$, $2$, and $3$, a full-prefix call visits
$1+2+3=6$ input rows in each Q, K, or V projection. The incremental path visits
$1+1+1=3$ rows per projection. It therefore reuses $3$ earlier K rows and $3$
earlier V rows. The newest query still reads all $t$ retained positions, so
this count does not claim constant-time attention or a measured speedup.

Errors are transactional. Two-token input, a full cache, model or head mismatch,
same-shaped rebuilt weights, a different RoPE configuration, and a nonfinite
append all return before cache bytes or logical length change.

## Give every decoder block its own state next

One attention layer can now preserve graph-free rotated keys and values across decode steps, reject stale or incompatible state, reset without reallocating, and reproduce its full-prefix newest-position output; Chapter 38 will compose one such cache per decoder block.

The current cumulative decoder still evaluates full prefixes. Chapter 38 will
create one cache from each block's actual attention layer, thread those caches
through prefill and one-token decode, and compare complete cached generation with
the uncached reference from Chapter 36.
