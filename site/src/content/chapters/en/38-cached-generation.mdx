## Predict both cache lengths before running

The fixture has $L=2$ decoder blocks, $H=2$ attention heads per block, model
width $D=4$, head width $d_h=2$, and context capacity $C=4$. It begins with
prompt token IDs $[0,1]$ and an empty model-wide cache.

Before revealing the trace, predict four facts:

1. Prefill sends both prompt positions through both blocks, so each block cache
   reaches logical length $2$ and shape $[1,2,2,2]$.
2. The first later token is token ID $2$ at absolute position $2$.
3. A successful decode advances both caches from length $2$ to length $3$; one
   block cannot remain behind the other.
4. The selected EOS token is returned to the caller but is not decoded when no
   later logits are needed.

The final prompt logits are
$[1.768374438,0.208825256,1.056205728,-0.451857108,0.388467944]$. After token
$2$, the next logits are
$[0.032908910,-0.679583624,1.408381841,0.525525421,-0.588014095]$. At both
boundaries, the cached and complete-prefix results have an unrounded maximum
absolute difference no greater than $2\times10^{-12}$; the displayed difference
is $0.000000000000$.

The restored checkpoint has context capacity $2$. It uses prompt $[0]$ and RNG
state `0x9e3779b97f4a7c38`. Both generation paths select $[4,4]$, decode literal
text `44`, consume matching sampling draws, finish with the same RNG state, and
stop at the context limit. Cached prefill reaches length $1$; the first $4$ is
decoded and advances the cache to length $2$; the second $4$ is selected from
those logits and returned, then context-limit stops before decoding it. With
token $4$ configured as EOS, both paths stop after selecting $[4]$ and perform
$0$ later decode-token forwards.

## Count attention-score cells, not total runtime

Hold batch size, layer count, head count, and head width fixed. Over a final
retained length $T$, the two score-cell totals grow as

$$
\sum_{t=1}^{T}t^2\in\Theta(T^3),\quad \sum_{t=1}^{T}t\in\Theta(T^2)\,.
$$

At retained length $t$, complete-prefix replay rebuilds a dense causal score grid
with $t^2$ entries for every fixed batch-layer-head lane. A cached step forms
only the newest query's row of $t$ scores against all retained keys. Summing
those per-step quantities from $t=1$ through $T$ gives the two growth classes.

This comparison is deliberately narrow. Cached attention is not constant-time:
the newest query still scans a prefix that grows with $t$. The formula does not
count projection or MLP work, memory traffic, allocation behavior, total runtime,
or wall-clock speedup.

For the exact fixture, batch $1$, $2$ blocks, and $2$ heads give a fixed factor
of $4$. Serial prefill plus decode forms
$4(1+2+3)=24$ cached attention-score values. The two independent reference calls
at lengths $2$ and $3$ form $4(2^2+3^2)=52$ values.

These fixture schedules are intentionally different. The cached execution visits
retained lengths $1$, $2$, and $3$, while the chapter makes only two independent
complete-prefix checks, at lengths $2$ and $3$. Thus $24$ and $52$ are measured
counts for the actual calls, not both asymptotic sums evaluated at $T=3$.

{/* chapter-section:symbol-glossary */}

## Keep retained length and final length separate

- $t$ is the current retained prefix length. It is also the number of keys read
  by the one newest cached query.
- $T$ is the final retained length covered by the comparison.
- $t^2$ is the complete-prefix score grid rebuilt at length $t$ for each fixed
  batch-layer-head lane.
- $\sum_{t=1}^{T}$ accumulates score-cell work from retained length $1$ through
  retained length $T$.
- $\Theta(T^3)$ is the growth class of repeated complete-prefix score grids when
  the omitted factors remain fixed.
- $\Theta(T^2)$ is the growth class of cached newest-query score rows under those
  same fixed factors.

The cache itself still stores one logical K/V prefix per block with shape
$[B,H,t,d_h]$. Equal shapes do not make two caches interchangeable: their rows
were produced at different depths of the decoder stack.

## From causal stacks to prompt and decode phases

A causal Transformer decoder can generate one token at a time by replaying the
complete known prefix, but that stateless interface rebuilds earlier attention
score grids and key/value projections on every later call.

[Attention Is All You Need](https://arxiv.org/pdf/1706.03762) establishes the
causal stack. Vaswani and colleagues describe a stacked autoregressive
Transformer decoder whose masked self-attention prevents a position from reading
later positions; their encoder-decoder architecture also includes cross-attention
and does not specify a KV-cache API.

[Fast Transformer Decoding: One Write-Head is All You Need](https://arxiv.org/pdf/1911.02150)
makes previous state explicit. Shazeer's incremental self-attention receives
previous key and value tensors, appends the current projected key and value, and
returns the updated state; the paper's contribution is multi-query attention, not
a claim to have invented KV caching.

[Efficient Memory Management for Large Language Model Serving with PagedAttention](https://arxiv.org/pdf/2309.06180)
continues the road into modern LLM inference. Kwon and colleagues separate a
prompt phase from sequential generation, describe later iterations reusing
cached keys and values while computing only the newest pair, and account for
KV-cache state across Transformer layers and heads.

Incremental decoding made previous key/value tensors explicit state, and later
LLM serving work separated one prompt phase from sequential generation while
retaining key/value state across decoder layers and heads.

Model-wide cached generation prefills one independent cache per decoder block
and advances every block only when later logits are needed. In the exact
fixtures, newest-position logits agree with complete-prefix references within
tolerance, and restored cached generation matches selected tokens, sampling
draws, final RNG state, and stopping reason.

The executable connects that progression to measured work. Across four
batch-layer-head lanes, serial cached rows at retained lengths $[1,2,3]$ contain
$24$ attention-score values. The two complete-prefix calls at lengths $[2,3]$
contain $52$, so this exact schedule avoids $28$ score values. These are tensor
element counts, not a paging or runtime measurement.

Exact model binding, all-block commit, reset, counters, errors, and serial prompt
processing are this course's local correctness choices rather than policies
defined by the cited papers.

Paging, sharing, eviction, and production memory management remain outside this
chapter. The contiguous cache here isolates the correctness boundary needed
before those serving concerns can be studied.

## Prepare every block, then commit the stack

Chapter 37's layer primitive now has an internal prepare boundary. It calculates
the candidate newest output and K/V row without changing logical state. Its
ordinary public call still prepares and immediately commits one layer, while the
model-wide path can hold one prepared result per block.

<RustSource
  path="rust/crates/llm-from-scratch/src/attention/incremental.rs"
  region="incremental-attention"
  caption="Prepare one candidate layer append and commit it only at the chosen boundary"
  label="Rust source for prepared Chapter 38 incremental attention"
/>

`DecoderKvCache::new` takes the actual decoder. It allocates one fixed-capacity
`LayerKvCache` per block and records the exact decoder configuration plus every
parameter-node identity. The state therefore rejects rebuilt equal-valued weights
and changed positional or decoder configuration, even when all visible dimensions
match.

`prefill` accepts a validated nonempty prompt only while state is empty. This
teaching implementation sends prompt rows serially through the same one-row path,
which keeps the state transition transparent; it is not an optimized parallel
prefill kernel. `decode` accepts exactly one in-vocabulary token only after
prefill and before capacity is full.

For each row, the decoder runs embedding, every block's pre-norm attention and
feed-forward residual path, final RMSNorm, and tied vocabulary projection. Every
block prepares its candidate append first. Only after all later calculations
succeed do the layer caches, common length, phase counts, and score-cell counts
advance together.

full cache remains at length $2$.

## Predict before checking the evidence

1. How many layer caches does a two-block decoder own?
2. After prefill with two tokens, what is each layer cache's logical length?
3. Which absolute position does the first decode token use?
4. Why can a cache from rebuilt equal-valued weights not be reused?
5. How many cache appends occur across two prompt rows and one decode row?
6. Why does the fixture form $24$ cached attention-score values?
7. Does caching make the newest attention query constant-time?
8. If the first selected token is EOS, must that token be decoded?
9. What does reset change, and what does it retain?

Misconception: caches with equal shapes can be shared by different blocks. In
fact, each retained row depends on the hidden state entering its block, so block
$1$ cannot reuse block $0$'s K/V rows. The model-wide state also binds every cache
to the exact decoder parameters and configuration that produced it.

<details>
<summary>Check the nine predictions</summary>

1. The decoder owns $2$ layer caches, one for each block.
2. Both caches reach logical length $2$ and shape $[1,2,2,2]$.
3. The first later token uses absolute position $2$, equal to the old cache length.
4. Equal values and shapes do not preserve parameter-node identity or the exact decoder configuration recorded by the cache.
5. $2$ blocks times $3$ token rows gives $6$ coherent cache appends.
6. There are $1\times2\times2=4$ batch-layer-head lanes, and each forms $1+2+3=6$ score values, giving $4\times6=24$.
7. No. The newest query still reads $t$ retained keys at prefix length $t$.
8. No. EOS is returned as the selected token, and no later logits are needed.
9. Reset changes logical length, phase, and counters to zero while retaining the backing allocation and stored K/V values for reuse.

</details>

## Connect inference to the whole pipeline

The complete decoder can now retain compatible graph-free K/V state across all
blocks, prefill a prompt, decode selected tokens only when later logits are
needed, reset for reuse, and match the exact fixture's complete-prefix generation
decisions; Chapter 39 will connect that inference path to the full train,
evaluate, save, load, and generate pipeline.

That final chapter will exercise the whole road in one program: partition data,
learn and apply BPE, train and select the decoder, evaluate untouched data, save
and reload the checkpoint, prefill the prompt, generate through the model-wide
cache, and decode the resulting token IDs back to text.
