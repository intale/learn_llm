## Plan every update before you train

Run every step of a bounded decoder training plan, measure graph-free validation
loss at fixed checkpoints, and restore the earliest validation minimum without
consulting test data. The worked fixture trains the one-block decoder from the
previous chapter: vocabulary size $V=5$, residual width
$d_{\mathrm{model}}=4$, two attention heads, feed-forward width
$d_{\mathrm{ff}}=4$, context length $T=2$, and $144$ trainable scalars.

Train a deterministic one-block, 144-parameter decoder for eight fixed
mini-batch updates with an explicit four-segment learning-rate schedule,
global-norm clipping at $0.35$, and validation measurements at steps
$0,2,4,6,8$. Before executing the first forward pass, the trainer already owns
all of these decisions:

1. the update batches come only from `Train` and have fixed order;
2. every planned update has one finite positive learning rate;
3. each successful update uses `forward>backward>finite-check>clip>adamw-step>zero-grad`;
4. both reported losses are token-weighted means measured without a graph;
5. only `Validation` may select a state, while `Test` is rejected here.

The schedule is

$$
(\eta_1,\ldots,\eta_8)
=(0.040,0.040,0.025,0.025,0.015,0.015,0.008,0.008).
$$

All eight steps execute. Validation does not stop the run early. In this
fixture, the five validation losses are

$$
(1.918167,1.696310,1.687788,1.642599,1.595297),
$$

so the selected snapshot is $s^*=8$. That happens to be the final planned
state in this fixture; the selection rule itself does not prefer the last state.

## Update on train, choose on validation

The complete boundary is

$$
\theta_{s+1}=\operatorname{AdamW}\!\left(\theta_s,\nabla_\theta\mathcal{L}_{tr}(\theta_s)\right),\quad s^*=\arg\min_s\mathcal{L}_{va}(\theta_s)
$$

The two losses have different jobs. The gradient comes from
$\mathcal{L}_{tr}$ and changes the parameters. The value
$\mathcal{L}_{va}$ is measured after selected update counts and may replace
the saved candidate, but it is never differentiated and never updates the
decoder.

For a raw gradient $g_s$ and ceiling $c=0.35$, the trainer applies one global
scale across every parameter tensor:

$$
\alpha_s=\min\!\left(1,\frac{c}{\lVert g_s\rVert_2}\right),
\qquad \widetilde g_s=\alpha_s g_s.
$$

The scheduled optimizer call is therefore more explicitly

$$
\theta_{s+1}=\operatorname{AdamW}_{\eta_s}
\!\left(\theta_s,\widetilde g_s,m_s,v_s\right),
$$

where the rate $\eta_s$ changes at declared boundaries while the moment states
$m_s$ and $v_s$ continue across those boundaries.

Validation averages by predicted-token count, not by number of batches. If
validation batch $j$ contains $n_j$ target tokens and has mean loss
$\mathcal{L}^{(j)}_{va}$, then

$$
\mathcal{L}_{va}
=\frac{\sum_j n_j\mathcal{L}^{(j)}_{va}}{\sum_j n_j}.
$$

On an exact tie, strict comparison retains the earlier candidate. Equivalently,

$$
s^*=\min\left\{s:\mathcal{L}_{va}(\theta_s)
=\min_k\mathcal{L}_{va}(\theta_k)\right\}.
$$

## Keep steps, gradients, and partitions distinct

- $\theta_s$ is the complete stable-name decoder state before update $s$.
- $s=0$ names the initialized state; $s\geq1$ names completed updates.
- $\mathcal{L}_{tr}$ is next-token loss from the training partition only.
- $g_s=\nabla_\theta\mathcal{L}_{tr}(\theta_s)$ is the raw finite gradient.
- $\widetilde g_s$ is the globally clipped gradient consumed by AdamW.
- $\eta_s$ is the predetermined learning rate for update $s$.
- $m_s$ and $v_s$ are Adam's continuing first- and second-moment states.
- $\mathcal{L}_{va}$ is graph-free validation loss used only for selection.
- $s^*$ is the earliest measured validation minimum.

The names `Train`, `Validation`, and `Test` are concrete `Partition` variants in
the program. In the explanation, their roles are conceptual: training fits,
validation selects, and test evaluates once after selection. A lower training
loss cannot substitute for held-out validation evidence.

Fresh optimizer outputs create an ownership issue as well. AdamW returns new
parameter leaves. The decoder's embedding, block, normalization, and tied
projection handles must all be rebuilt from those same leaves before the next
forward pass. Merely replacing a separate registry would leave the component
handles pointing at stale parameters.

## From training-only reports to validation-selected LLM checkpoints

Move from fitting and reporting one training state toward predetermined
mini-batch updates that produce periodic validation candidates while a separate
test partition stays unopened. This is a history of the training practices on
the road to modern LLMs, not a history of implementation languages.

[A Neural Probabilistic Language Model](https://www.jmlr.org/papers/volume3/bengio03a/bengio03a.pdf)
provides an early neural-language-model boundary. Bengio and colleagues
separate training, validation, and test text, explicitly associate validation
with model selection and early stopping, and describe stochastic per-example
parameter updates for a feed-forward neural language model. Full-corpus or
per-example updates and training-set-only reporting do not by themselves define
a scalable update cadence or an independent rule for choosing among candidate
language-model states.

[Sequence to Sequence Learning with Neural Networks](https://arxiv.org/pdf/1409.3215)
adds practical sequence-training controls. Sutskever, Vinyals, and Le report
batches of sequences, a predetermined learning-rate reduction policy, and
rescaling when the global gradient norm crosses a fixed threshold in a
recurrent sequence model.

[Attention Is All You Need](https://arxiv.org/pdf/1706.03762) carries those
ideas into the Transformer era. Vaswani and colleagues train Transformers with
token-budgeted batches, a step-indexed warmup and inverse-square-root schedule,
and periodically written checkpoints. Their reported checkpoint averaging is
not the validation-minimum selection rule implemented here.

[Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer](https://www.jmlr.org/papers/volume21/20-074/20-074.pdf)
makes the selection boundary explicit. Raffel and colleagues save fine-tuning
checkpoints at a fixed cadence, choose the one with the best validation
performance, and explicitly avoid using the test set for model selection.

[Language Models are Few-Shot Learners](https://arxiv.org/pdf/2005.14165)
connects the controls to decoder-only scale. Brown and colleagues carry Adam,
scheduled learning rates, token-based batch scaling, and global-gradient-norm
clipping into decoder-only language-model training at GPT-3 scale.

Neural language-model work separated train, validation, and test
responsibilities; sequence and Transformer systems added mini-batches, explicit
schedules, clipping, and periodic candidates; later text-to-text work stated
that validation chooses a checkpoint so test data does not perform model
selection. Decoder-only LLM training repeatedly forms token batches,
differentiates the training objective, controls gradient magnitude, applies a
step schedule, and measures held-out validation candidates while reserving test
evidence for a later once-only evaluation.

These papers use different architectures and recipes. The course's fixed seed,
exact cadence, eight-step budget, and earliest-tie rule are local teaching
choices, not universal properties of LLM training. The small runnable contrast
shows why the selection signal matters: a training-only trace chooses its final
entry, while a held-out validation trace can choose an earlier one.

## Make the cumulative training boundary explicit in Rust

`LearningRateSchedule` stores exactly one finite positive rate per update.
`TrainerConfig` requires validation at $s=0$, strictly increasing checkpoint
steps, a final checkpoint after the last update, and one positive finite global
norm ceiling. The operation order is data, not an implication hidden inside a
loop.

therefore reaches AdamW with norm $0.35$. That observation is fixture evidence,
not a requirement that all real LLM updates clip. The generic trainer also
accepts finite gradients already below the ceiling.

## Test the information boundary and state ownership

1. Change the update epoch from `Train` to `Test`. Predict which preflight error
   occurs and why neither the caller's decoder nor optimizer may change.
2. Replace checkpoint steps $[0,2,4,6,8]$ with $[0,2,4,6]$. Explain why a
   final candidate is required after all planned updates.
3. Construct validation losses $[1.8,1.6,1.6]$. Predict which checkpoint strict
   comparison retains and relate it to the definition of $s^*$.
4. Average two batch means without token weights when their token counts differ.
   Compare that result with the token-weighted formula above.
5. Replace only the parameter registry after AdamW and leave component handles
   untouched. Identify which state the next decoder forward would use.
6. Draw a line between the five validation markers. List the unmeasured claims
   that line introduces, then remove it and recover the discrete evidence.

## Freeze the selected decoder for one test pass

The cumulative decoder can now execute a complete bounded training plan and
return a frozen validation-selected state; Chapter 34 will score that state once
on the test partition and compare it fairly with the frozen baseline.

That next step must not tune the schedule, clipping ceiling, number of updates,
or checkpoint choice after seeing test results. Chapter 33 ends with model
selection complete and `test_reads=0`; Chapter 34 will open the held-out test
partition exactly once for evaluation rather than selection.
