## Trace one token before learning any details

Start with the prompt <code>A</code>. A tokenizer turns that text into token IDs.
Embedding lookup replaces each ID with a learned feature vector. That vector enters
a stack of decoder blocks. Every block first uses normalized causal attention to
mix information from the current decoder-input position and earlier input
positions, then uses a normalized SwiGLU branch to transform features at the
current position. Training shifts targets by one position, so this allowed
diagonal never exposes the token being predicted. Residual additions keep the
main representation moving through both branches.

After the final block, RMSNorm controls the feature scale once more. The tied
vocabulary head produces one logit for each vocabulary item at every sequence
position. Softmax and the decoding policy turn those logits into a next-token
choice. The chosen token ID is appended to the token-ID sequence. The next cached
decode starts from that ID's embedding; it does not detokenize and tokenize the
whole growing sequence again.

Training reuses that same tokenizer, embedding lookup, decoder stack, and
vocabulary head to produce logits. It branches before sampling: the observed next
token becomes the target, loss measures the prediction, reverse mode sends
gradients through the shared blocks, and AdamW updates their weights. Validation
selects a state; final evaluation measures that already frozen choice. Those
operations create and check the model, but they are not extra layers traversed for
every generated token.

{/* chapter-section:formula */}

## One objective connects all the blocks

A causal language model assigns a sequence probability by multiplying one
next-token conditional probability at every position:

$$
P_\theta(z_{1:T})=\prod_{t=1}^{T}P_\theta(z_t\mid z_{<t})
$$

The tokenizer defines the token sequence, the decoder computes features from the
earlier prefix, the vocabulary head and softmax produce each conditional
distribution, and training adjusts parameters to increase the probabilities of
the observed next tokens.

{/* chapter-section:symbol-glossary */}

## Read the notation

- $P_\theta$ is the probability model defined by all learned parameters; its
  arguments specify a sequence or conditional event.
- $\theta$ is the collection of learned embeddings, normalization gains,
  attention weights, and feed-forward weights.
- $z_{1:T}$ is one complete sequence of token IDs.
- $T$ is the number of tokens in the sequence.
- $t$ is the current token position.
- $z_t$ is the observed token at the current position.
- $z_{<t}$ is all earlier tokens available as causal context.
- $\prod_{t=1}^{T}$ means multiplication of one conditional next-token
  probability at every position.

## A short road to the modern block diagram

Count n-grams condition on a fixed short context and cannot learn reusable
distributed features or content-dependent access to a longer prefix. Neural
language models learned distributed token representations, the Transformer
supplied masked self-attention over the prefix, and later autoregressive
Transformer language models scaled the same next-token objective. A modern
decoder-only LLM repeatedly transforms token features with normalized causal
attention and gated feed-forward branches, then projects the result to a
next-token distribution used by training or generation.

[A Neural Probabilistic Language Model](https://www.jmlr.org/papers/volume3/bengio03a/bengio03a.pdf)
supports the earlier boundary. Bengio and colleagues contrast n-gram generalization
with a neural probability function that learns distributed word representations;
their model predates the Transformer and this course's decoder block.

[Attention Is All You Need](https://arxiv.org/pdf/1706.03762) supports the later
architecture boundary. Vaswani and colleagues define the Transformer and mask
decoder self-attention against later positions; their published system is an
encoder-decoder model, not this course's decoder-only topology.

[Language Models are Few-Shot Learners](https://arxiv.org/pdf/2005.14165) supports
the scaling boundary. Brown and colleagues describe GPT-3 as a scaled autoregressive
language model; its scale and measured capabilities do not transfer to the tiny
reference model used here.

The progression is therefore about language models: short count contexts, learned
distributed features, masked attention over a prefix, repeated decoder blocks, and
scaled autoregressive training. Rust gives us executable evidence for the small
version; it is not the subject of the history.

## Put every later lesson in one place

The inference section is the path a trained model follows to choose a token. The
decoder-block section opens the repeated block, including both residual additions
and the cache owned by attention. The learning section reuses the first five
blocks through logits, then branches to loss and updates. The numeric foundation
supports both paths, evaluation checks the selected state, and a checkpoint
preserves the state that inference can use.

That numeric foundation is shared: tensor operations execute during inference as
well as learning. Recording the operation graph and propagating gradients are the
learning-only responsibilities.

Each card links to the chapter or chapters that build it. Read the compact map once
for orientation, then return to it whenever a new formula needs a home.

## Check your first mental model

1. Which part first turns token IDs into learned features?
2. Which branch lets a query use its current decoder input and earlier inputs without reading its prediction target?
3. Why does one decoder block contain two residual additions?
4. Which part emits one score for every vocabulary token?
5. Does AdamW run while an already trained model generates text?
6. What does the KV cache retain, and where does that state belong?
7. Where does the chosen next token go?
8. Which chapter joins every part into a functioning program?

Misconception: an LLM is one opaque neural-network box. The model is better
understood as a composition: token interface, learned feature path, repeated
decoder blocks, vocabulary prediction, and a separate process that learns and
checks the weights.

## Start the implementation path

Chapters 1 through 7 establish text, tokenization, causal examples, a count
baseline, and language-model metrics. Chapters 8 through 23 build the numeric and
learning foundation. Chapters 24 through 32 assemble the decoder. Chapters 33
through 38 train, evaluate, persist, sample, and cache it. Chapter 39 runs the whole
tiny LLM.

Chapter 1 starts with the boundary every later block depends on: text is not yet a
model input. It must first become stable token IDs.
